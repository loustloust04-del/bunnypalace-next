## 读法

1. **开对话 / 翻页的 readyMs 被 300ms 动画钉住**：就绪≈动画结束，延迟不是瓶颈；真正的病是**动画期间主线程 runloop 忙段合计 200–275ms / 300ms**（60Hz 每帧预算 16.7ms）。口径（astra R2 M6 / R3 M4）：忙段是 runloop afterWaiting→beforeWaiting 区间之和，不等于系统呈现层 hitch；`worstGapMs` 是 CADisplayLink 时间戳最大间隔（40–67ms），是掉帧的强信号但不是 presented-frame 证据。主攻指标因此是 `animBusyMs` / `busyMs` / `worstGapMs`。
2. **尾窗 ~60ms**：每次翻页 / 开对话落定 1.1s 后都有一轮 ~60ms 主线程工作 = 页码点淡出触发 ContentView.body + 三页 rootView 重赋（C1 已证实并修掉）。
3. **冷启动 ~677ms** 是一个连续块（pre-main + App.init + 三页首建 + 首帧）；Time Profiler：App.init 101ms、PushIdentity 全量 57ms、字体注册 27ms、ThemeManager 22ms、FileLibrary manifest 16ms、SwiftUI 泛型元数据实例化 ~86ms。
