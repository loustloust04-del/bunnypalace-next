请你读一段真实的私人对话，把里面值得长期记住的东西写成记忆条目。「{u}」是用户，「{c}」是陪她聊天的 AI。

材料分三块：
- **新对话**：一条一行，形如 `#编号 时间 · 说话人：正文`。只有这一块里的事能记，`msgs` 只能写这一块里的编号。请完整读完。
- **前文**：新对话之前的原文。只是让你看懂指代和前因，**不要把前文里的事写成条目**。
- **已记的卡**：档案里已经有的。已经记过、没有新情况的事不要再写；这段新对话里有了新情况的，写一条完整的新条目。

**这个窗口的名字是「{窗口名}」**，这段新对话的时间是 {起} 到 {止}。她同时开着很多个窗口，每个窗口里都有一个{c}；这些条目以后会被**别的窗口**里的{c}读到。

（这里原来是几句主人的原话，对照用时略去）
- 她认可的一把尺子：**一条好的记忆 = 三个月后，{c}在一个全新的窗口里翻到它，不需要再翻原文就能直接用，用它来更好地对待她。** 翻到了没法用的（不知道在说什么、不知道现在还作不作数），要么写到能用，要么不写。
- 一条 = 一件完整的事：一个能独立使用的事实，连同它的直接原因和结果，写在一起。

要做到：
1. **谁说的要分清。** 她亲口说的事，和{c}的解读 / 观察 / 建议 / 台词，是两种东西。角色扮演里的话、几分钟后就反悔的气话，不是她的现实或决定。交之前逐条回出处核对：这句是谁说的？是不是在演？后面有没有改口？
2. **事实和「该怎么对待她」分开**：「她是什么样 / 发生了什么」是 fact；「这种时候要怎么做 / 不要怎么做」是 instruction。同一件事只记一次，不要事实版、做法版各写一条。
3. **不要撕。** 一件事就是一条，条目里可以有三四句；「写短句、一句一个信息点」说的是条目内部怎么写。也不要反过来把几件不相干的事塞进一条。
4. **不要悬空的指代。** 「这个窗口」「这次」「今天」「昨天」「现在」「最近」「刚才」这类要站在原地才读得懂的词不许出现：说到这个窗口或这个窗口里的{c}，就写窗口名（「{窗口名}」窗口的{c}）；说到时间就写日期。
5. **不记流程和琐碎。** 「谁问了什么、谁回了什么」的对话经过不是记忆；一次性的小事不记。
6. **会变的状态标出来**（`volatile`）。
7. 她的原话值得留的用引号留着。主语写在 `subject` 里，正文不用每句都以名字开头，但正文里出现的其他人要写名字。

只输出一个 JSON 数组，前后不要任何别的文字。每个元素：
{"subject":"这条是关于谁 / 什么的（名字）","type":"fact 或 instruction","origin":"said（她亲口说的或对话里直接发生的）/ assistant（{c}说的，她没确认也没反驳）/ inferred（推出来的）","volatile":true 或 false,"content":"正文","msgs":[出处的消息编号…],"since":"这件事从什么时候起成立（YYYY-MM-DD，说不清就不写这个字段）"}
大多数闲聊里没有值得长期记的事，那就少写；一条都没有就输出 []。
