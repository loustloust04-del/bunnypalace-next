## 〇、这一版为什么又重写

粟粟 10-22 原话：

> 试写台量化测提示词和管线准确度啊，所有写入abc不是都算写入吗。。｜卡片那个就是整理台啊，人整理。｜未来还有召回测试台，测记忆准确度，有效性，注入位置等等，这不就是跟训练大模型一样吗。等这个真弄好了之后再自动化甚至自动进化。auto research为什么牛逼rsi为什么牛逼不就是因为能找到想要优化的那个东西吗。我刚刚说的所有这几个工作台都在子app-记忆-审计台里。然后审计台变成很多方形小组件样式每个点进去就是一个台。

前三版都把试写台当「改提示词、看一眼」的工具。她要的是**评测场**：固定测试集 + 被测对象（提示词 + 管线 + 模型）+ 跑 + 打分 + 历次对比。先做到「人能测准」，自动优化以后做，但数据结构现在就要能被程序读。第三版里两点保留：一次跑 = 用例 × 配方 × 模型的组合、写手抽成接口。

## 一句话

审计台变成方块小组件网格，一个方块一个「台」，台是注册出来的、以后能继续加：现在有**整理台**（就是现在审碎片的卡片页，人工整理）、**wiki 台**（含整理提案）、**试写台**、**召回测试台**（灰着）。试写台是所有写记忆环节共用的评测骨架：选一个**测试集**（固定输入 + 答案 / 标签）→ 选几个**配方**（提示词版本 + 管线参数）× 几个**模型** → **跑** → 每种写手按自己定义的**主分**打分（格式这类硬规则自动算，对不对靠她判过的标签）→ 跑分和完整日志都存下来，**历次对比**。第一刀接 C2（有现成测试集和标签）和 A2 / A3 / A4（A 线改版要用），C3 第二刀。

**不做**：不改任何已存的记忆数据和存储格式；不做 A 线改版本身；不做 C3 接入、召回测试台、自动优化 / 自动进化（只留数据上的路）；不精修视觉。

## 三、试写台骨架：所有写手共用的五样东西

### 3.1 名词

| 名词 | 是什么 | 例子 |
|---|---|---|
| **测试集** | 一组**冻结的**输入（用例）+ 每个用例的答案 / 标签。建好以后输入不再变，所以历次跑分能比 | 「C2 质量探针」12 个用例；「我的 A2 · 10 月」8 段真对话 |
| **用例** | 一份输入 + 它的标签 | 探针第 08 段（公主怕水那段）+「不该记：岚舟怕水（是戏）」 |
| **标签** | 答案的一条：该有的 / 不该有的 / 要点 / 判断。来源：探针预期、她在结果上判的、整理台和提案里她做过的决定 | 「应记：岚舟乳糖不耐」「不该记：翻译请求」 |
| **配方** | 被测对象里「我们能改的」那部分：提示词版本（system / user 两份模板）+ 管线参数（这个写手自己的开关和数字） | 「C2 · 修 subject 版」；「A3 · A 线改版稿 · 长窗口阈值 8」 |
| **跑** | 测试集 × 几个配方 × 几个模型，一次跑完；结果、请求原文、花费、她的判断、分数全存 | 「10-22 21:03 · C2 探针 · 现行 / 修 subject × Haiku / Sonnet」 |
| **分** | 每种写手自己定义的**主分**（要优化的那个数）+ 几个副分 + 护栏（不过就不算数） | C2 主分 = 判对的条数 / 产出条数 |

### 3.2 存在哪、长什么样（都能被程序读，为以后自动化留路）

全部是 JSON，带 `schema` 版本号，按楼层放在**楼层目录下的 `bench/`，和 `memory/` 平级**（`FileLibraryStore.memoryRoot` 的上一层 + `bench`）。实现时核过：`memory/` 下的点开头目录只对 `wiki/` 隐藏（`FileLibraryMemoryFolder.isHiddenWikiPath`），放 `memory/.bench` 会被助手 fs_list / search / read / write 看到和改、fs_search 还会扫大文件；`bench/` 不在 `memory/` 也不在 `filesystem/`，助手工具和文件库都看不到，楼层迁 iCloud 只搬 `filesystem/` 和元数据，它留在本地：

```
<楼层目录>/bench/
  sets/<测试集id>.json        测试集：用例（冻结的输入）+ 标签
  recipes/<写手>.json          配方：她存的版本 + 正在用的那份
  runs/<跑id>/run.json         一次跑：配置快照、每格结果、她的判断、分数
  runs/<跑id>/requests.jsonl   完整日志：每次请求送了什么、回了什么、token、钱、耗时
```

内置（编造数据、只读、随 app 走）：`Resources/MemoryBench/memory-bench-c2-probe.json`——C2 质量探针，**测试代码和 app 用同一份**（`testC2QualityProbeLive` 改成读它，不再在测试里写死）。

形状（示意，字段名实现时定）：

```jsonc
// 测试集
{ "schema": 1, "id": "c2-probe", "name": "C2 质量探针", "writer": "c2",
  "source": "builtin | floor | imported", "revision": "<内容哈希>",
  "cases": [
    { "id": "08", "input": { /* 写手自己的冻结材料，C2 = 带日期的几轮对话 */ },
      "labels": [
        { "id": "08-n1", "kind": "不该记", "text": "岚舟害怕水（扮演里的台词）", "keys": ["怕水"], "from": "她判 10-23" } ] } ] }

// 配方（一个版本）
{ "schema": 1, "id": "…", "writer": "a3", "name": "A 线改版稿 10-17", "parent": "<从哪版改来的>",
  "system": "<模板>", "user": "<模板>", "params": { "长窗口阈值": 8 }, "checks": "a-line", "savedAt": "…" }

// 一次跑
{ "schema": 1, "id": "…", "at": "…", "writer": "c2", "set": { "id": "c2-probe", "revision": "…" },
  "recipes": [ /* 跑的时候的配方快照 */ ], "models": ["haiku-4-5", "sonnet-4-6"], "scoreVersion": 1,
  "cells": [ { "case": "08", "recipe": "…", "model": "…", "output": "…", "items": [ /* 解析出的条目 */ ],
               "checks": [ … ], "usage": { "in": 3200, "out": 410 }, "usd": 0.004, "ms": 5100, "error": null } ],
  "judgments": [ { "cell": "…", "item": 2, "verdict": "错", "label": "08-n1", "by": "她 | 自动配" } ],
  "scores": [ { "recipe": "…", "model": "…", "main": 0.86, "parts": { "错条": 4, "产出": 29, "应记召回": 0.93 } } ] }
```

- 配方带 `parent`：改了哪版来的，以后能画「进化树」。
- 跑存**配方快照**，不存引用：版本后来改了，老的跑照样能复算、能看。
- 分数由可插拔的打分器（`MemoryBenchScorer`）从 `cells + judgments` 算出来，每个分带打分器 id + 版本；打分规则改了 / 换了，老的跑能重算，老分也不丢。
- 测试集带 `revision`（**只哈希用例 id + 输入**，标签不算——判断回流会不断加标签，不能因此断掉历次线）：只有同一个 revision 的跑才放进同一条「历次对比」；输入改过就另起一条线，并标出来。
- 保留：分数和判断永远留；`requests.jsonl` 和原始输出 30 天后清，她钉住的跑不清。
- 时间一律存「1970 起的整毫秒」整数（ISO8601 只到秒，读回来和内存里不相等）；跑的状态多一个「中断」（跑到一半 app 没了，做完的格子留着）。

### 3.3 写手接口（`Services/MemoryBench/MemoryBenchWriter.swift`；目录不叫 `Bench`，免得和现有的性能基准 `BenchIsolation` 混）

试写台只认这个接口。一个写手交出：

| 项 | 说明 |
|---|---|
| 身份 | 编号、名字、记账用途（试写一律 `.memoryTrial`） |
| **建用例** | 从真材料冻结出一个用例（A2：窗口里的一段；A3：一个窗口连同当时的 A2 段；A4：一天的 A2 标题；C2：一截对话；C3：一个主题的原料包），只读、后台 |
| **标签种类** | 这个写手的标签有哪几种（应记 / 不该记 / 要点 / 弯 / 必须提到…） |
| **变量清单** | 模板能用的变量（名字、说明、示例），由用例的冻结材料填 |
| **内置配方** | 第一个永远是「现行」，渲染结果和正式写手逐字相同（快照测锁住）；可以再带别的（如「A 线改版稿」） |
| **管线参数** | 这个写手除提示词以外能调的东西（名字、类型、默认值） |
| **怎么调模型** | `.single(system, user)` 或 `.agent(system, user, 工具, 出口)`；第一刀只实现 `.single`，`.agent` 占位留给 C3 |
| **解析 + 检查** | 输出 → 条目 / 块；硬检查、软检查（只辅助，算进护栏或副分） |
| **自动配标签** | 新输出的条目和已有标签对一对（关键词命中），配上的预填判断，她只确认 |
| **打分** | 挂一个或几个 `MemoryBenchScorer`（可插拔，⧫Q1）；这一刀所有写手共用一个占位打分器：主分 = 已判条目里「对」的比例，副分 = 格子数 / 出错格 / 条目数 / 已判 / 判错 / 偏弱 / 检查没过 / token / 钱 |
| **换上**（可选） | 「设为正在用」接到正式写手；没有就只能测不能换 |
| **现在存着的**（可选） | 用例来自真材料时，把当时真存下的那份拿来并排 |

模板引擎 `Services/MemoryBench/PromptTemplate.swift`：`{{变量}}`、`{{#如果 条件}}…{{否则}}…{{/如果}}`（条件 = 变量有没有 / 真假 / `段数 <= 8` 这类比较）、`{{#每 段}}…{{/每}}`（里面有这一份的字段和 `{{序号}}`、`{{是第一个}}`、`{{是最后一个}}`，外层变量照样能用）。写错带行号提示，那一版不能跑。

## 四、各写手：测什么、标签是什么、主分是什么

> **粟粟 10-23（⧫Q1）**：「这个暂时不知道准确数，因为比较主观。你先别细究这个，弄个架子就行。」→ **打分做成可插拔**：每个写手的打分是一个接口（`MemoryBenchScorer`，输入 = 一次跑的格子 + 判断，输出 = 主分 + 若干副分），这一刀只给**最简单的占位实现**（能算出数、能存、能对比）；一次跑可以挂多个打分器，跑分记录里每个分都带打分器 id 和版本，换口径不丢老记录。下表的「主分」只是**以后的候选**，不是唯一口径，不细抠。
>
> 原则（候选，不写死）：主分一个数 = 要优化的那个东西；格式这类硬规则当护栏；其余副分帮她看原因。对不对由她判，程序只做能字面算的部分和预填。

| 写手 | 测试输入（用例） | 答案 / 标签 | 主分（要优化的那个数） | 副分 / 护栏（自动算的） |
|---|---|---|---|---|
| **A2** 上下文摘要 | 她真窗口里的一段原文 + 当时的上一段（冻结） | 每个用例她写 2–5 条「要点」（这段里必须记下的事），可选：「不该写」的内容 | **要点覆盖率** = 命中的要点 / 要点总数（程序按关键词预判，她确认） | 护栏：硬格式（标题 + 经过 + 原话）、不叫她「用户」。副分：**原话逐字率**（【原话】每句能不能在原文里找到，纯字面）、标题软规则（≤15 字、不以我 / 你 / 我们开头）、经过字数、连接词次数、关键词有没有 |
| **A3** 窗口总结 | 一个窗口：当时的全部 A2 段 + 原文尾巴（冻结；A2 后来变了也不影响这个用例） | 她列这个窗口的 3–6 个「弯」（话题切换 / 结论 / 情绪转折） | **弯覆盖率** = 写到的弯 / 弯总数 | 护栏：格式块齐、不叫「用户」。副分：长度在不在档（按段数四档）、原话逐字率、关键词数、走向里有没有「待续 / TODO / 下次」、连接词 |
| **A4** 时间轴主调 | 一天的 A2 标题清单（冻结） | 每天她写 1–3 个「这天必须提到的事」，或直接写一句她觉得对的主调 | **她判「能用」的天数比例**（一句话最难字面量化，就直接让她判；程序预填「必须提到的都提到了」） | 护栏：有主调、≤40 字。副分：必须提到的命中数、有没有写感受 / 评价词 |
| **C2** 碎片池 | 一截对话（探针 12 段；以后也从整理台导入真对话） | 每段「应记」事实（带关键词）和「不该记」内容（带关键词）；她在结果上判的对 / 错 / 偏弱 | **准确率** = 判对的条数 / 产出条数（她判的就是「该丢的丢没丢」，Haiku 那 4 条错就扣在这里） | 应记召回率（应记命中 / 应记总数）、subject 干净率（不是「X 的 Y」短语）、speaker / 类别对不对、拒收张数（`parse` 的拒收原因）、条数 |
| **C3 种子** | 真测试集A：楼层人设 + 60 份 CC 记忆（冻结） | 她对目录每一条的批 / 改 / 驳，对正文的批 / 改 / 驳 | **目录原样通过率** = 不改就批的目录条数 / 目录条数 | 改后通过率、驳回率、正文通过率、轮数、花费；护栏：交了提案、出处都活着 |
| **C3 日常** | 一个主题 + 当时的原料（碎片、A 线、已有页，冻结） | 她对提案条目的批 / 改 / 驳（现有 `wiki/.proposals` 里已经有她的历史决定） | **提案原样通过率** | 改后通过率、驳回率、引用活着率、轮数、花费 |
| **B 线** | 留位置：B1 / B4 是助手在聊天里调工具，要测得模拟一段聊天；B2 / B3 还没做 | — | — | — |

## 五、试写台页面

一个台里的路：**测试集 → 跑 → 分数 → 历次对比**。

1. **顶上**：写手分段（A2 / A3 / A4 / C2，以后 C3）；下面是这个写手的测试集列表（内置的 + 她建的，每个显示用例数、最近一次主分）。「＋ 建测试集」：从真材料挑（窗口 / 段 / 日期 / 对话截），或从整理台导入（C2）。
2. **点进一个测试集** → 三块：
   - **历次**（最上面）：同一个 revision 的每次跑一行「10-22 21:03 · 现行 · Haiku · 86%」，加一条小折线；能勾两次跑并排比。
   - **用例**：每个用例的输入摘要 + 标签（能加、改、删标签）。
   - **跑一次**：勾配方（最多 3 个，「现行」「A 线改版稿」、她存的、编辑框里没存的那份）× 勾模型（最多 3 个，默认这个写手设置里的那个）。按钮上方一行「12 个用例 × 2 个配方 × 2 个模型 = 48 次 · 约 $0.31」；**超过 60 次**变红「这次要跑 96 次，一次最多 60 次——少勾一个，或者先挑几个用例」，按钮灰掉，不默默截。同时最多 3 个请求。
3. **跑完的成绩页**：
   - **成绩表**（最上面）：每行一个「配方 × 模型」，列：主分（大字）、副分、护栏没过几格、花费、耗时；和上一次同配方比，涨了跌了标出来。
   - **逐个用例**：同一个用例，几个「配方 × 模型」的结果一张张并排（iPhone 横着翻，宽屏并排），**正文是主角**；条目旁边是配上的标签（「应记 ✓」「不该记 ✗ 混进来了」）和她的判断按钮（对 / 错 / 偏弱），没配上的标「待你判」；卡底一行小字：检查、token、钱。
   - 她判完，分数当场重算、存进这次的 `run.json`，判断同时回流成用例标签。
4. **配方编辑**（从「跑一次」里的配方点进去）：System / User 两个编辑框、变量清单、管线参数、检查规则（现行格式 / A 线新格式 / 不查），「另存为」（记 `parent`）/「存到这一版」/「改名」/「删掉」；内置配方只能另存。
5. **设为正在用**：成绩表某一行右边。写清后果（⧫Q3），确定后这层楼这个写手正式写就用它；写手二级页显示「自定义 · 外星 v2」，能恢复默认。

记账与日志：试写一律记 `.memoryTrial`「试写」，进写入预算合计、**不受写入预算拦**（全局预算闸照查）；不进健康状态；记忆日志每次跑记一条汇总（「C2 探针 · 48 次 · 主分 86% → 93%」，`trial` 标记，`latest` 跳过它）；完整请求在这次跑的 `requests.jsonl` 里。

## 九、风险

- **请求体金样**：不碰聊天组装，`PromptRealPathGoldenTests` 照跑一字不变；正式写手没设「正在用」时一行不变，「现行」配方由快照测锁成逐字相同。
- **审计台三段 / 整理提案的数据**：不动；回流成标签只读不写它们。
- **隐私**：她的真对话会被冻结进测试集（复制一份到楼层的 `bench/`）。和记忆文件同一层楼、同一个隐私级别（本地、不进 git、不随 iCloud），而且助手 fs 工具和文件库都看不到；内置测试集只放编造的。
- **钱**：一次跑可能几十次调用，所以先估算、设上限；钱算进写入预算，后台写手会更早停。
- **骨架过度设计**：第一刀只实现 `.single`、只接 C2 + A 线；`.agent`、C3、召回测试台只在接口和表里占位。
- **标签自动配会配错**：只当预填，判断以她点的为准；分数页标出「其中 N 条是自动配的」。
- **测试集冻结后会老**：真材料后来变了不影响用例，这是故意的；想用新材料就新建用例。
