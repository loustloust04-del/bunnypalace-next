# Review：小芽 v2 · P3 外观放权

- 日期：2026-09-26（🎩）
- plan：[plan-小芽-v2.md](plan-小芽-v2.md) §5 / §9 P3 · 提交 `173bb666`
- 验证：`AssistantAppearanceTests` 11 例 + 既有小芽测试全过；mac / iOS 双端 build；已装 Air。**试穿卡的真机观感、真机走一遍「提案 → 盖章 → 回桌面看 → 撤销」都没做**（要实聊触发工具）

## 1. 边界情况

- **盖章套当下值**：提案只存要改的几项 + 那几项的改前值。盖章时核「这几项现在还是改前值」→ 套到当下外观上存；她在提案之后改的别的项不会被盖回去（测试钉住）。改过同一项 → 失败让小芽重看。
- **针脚主屏**：`page2HomePresentation_v1 != free` 时，read_appearance 明说「不影响」，两个主屏工具直接报错不产提案，盖章也再拦一次。
- **单个图标**：撤销时原来没自定义 → 删 key 回默认图标；原来是「自己的图片」的图标，小芽的提案会把它换成符号（改前值里存着图片文件名，撤销能回去；图片文件本身 `save` 不会删）。
- **舞台**：`propose_stage_theme` 两端都有；撤销前核「现在还是她换的那个」，不是就要确认覆盖。
- **存盘失败**：`Page2AppearanceStore.save` 返回 false → 抛错 → 卡片红字失败、不写账。
- **试穿**：卡片直接把改前 / 改后的值传给 `Page2WallpaperView` / `Page2AppIcon(appearanceOverride:)`，不调全局 preview、不嵌编辑器；只在待盖章时画，盖完只剩对照行。

## 2. 与下一模块（P4 本地大脑）交互的风险

- **工具定义变多**：现在 iOS 上一共 18 个工具（查阅 5 + 创作 8 + 外观 4 + 读外观 1）。P0 实测 1.7B 在 3 个工具下全对，18 个时的准确率没测——P4 第一件事就是拿全量工具实测，差了再按包 / 按意图裁。
- **read_appearance 输出较长**（列了全部 app id），本地模型上下文紧，P4 的 token 预算要把它算进去。
- **`AssistantTools.execute` 现在是 `@MainActor`**（外观要读 MainActor 的 store）；P4 的本地 backend 在后台跑推理，但工具执行仍回主线程，别在后台直接调。

## 3. 技术债

- 试穿迷你主屏按 390×520 渲染再缩到 0.29，只画了前 12 个 app，和她真实桌面的排布（Page2 网格 / 文件夹 / 小组件）不一样——是「这套外观长什么样」的示意，不是她桌面的截图。
- `page2HomePresentation_v1` 这个键在工具层和工作台各读了一次（字符串字面量两处），没抽常量。
- Page2 主屏工具只在 iOS 编译；mac 上 read_appearance 只报舞台。
