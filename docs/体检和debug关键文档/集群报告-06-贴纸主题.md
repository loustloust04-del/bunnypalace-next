## D1 架构

**1. StickerViewModel 越界承担 View 层职责** — `ViewModels/StickerViewModel.swift:514-550` — D1 — P2
现状：VM 内直接弹 AppKit/UIKit UI（NSSavePanel.runModal / UIActivityViewController + 遍历 presentedViewController 链找 topVC）。
风险：导出/分享的呈现逻辑进了 ViewModel，不可测试，未来多 window/多 scene 下取错 window。

**2. WorldBookPanelView 在 View 内做导入解析与数据迁移** — `Views/WorldBookPanelView.swift:897-947` — D1 — P2
现状：handleWorldBookImport 在 View 里做 JSONSerialization 解析两种酒馆格式 + 建模 + 绑 profile；createNewBook/setScopeForBook 在 View 里 fetch "最近 lastOpenedAt 的对话" 当作"当前对话"。
风险：1099 行巨型 View 混业务逻辑；"最近打开 = 当前对话"的启发式在多窗口/后台切换下可能绑错对话。

**3. 单例集群（PetManager/TodoManager/DashboardManager/ThemeManager/TerminalKeyStore.shared）** — 各 Service 文件 — D1 — P2
现状：均为 UserDefaults 持久化的全局单例，Theme 静态属性硬耦合 ThemeManager.shared（Theme.swift:9-11）。
风险：可接受的务实选择，但 Theme→ThemeManager.shared 让所有用色代码无法注入测试主题；属已知折衷，非滥用。

## D3 并发

**1. @Observable UI 状态在后台执行器上被修改** — `ViewModels/StickerViewModel.swift:129-136, 197-204` — D3 — **P1**
现状：importImages/importImageData/updateStyle 是非隔离 async 函数（Swift 5.10 下跑在全局执行器），直接改驱动 UI 的属性（isImporting/importProgress），而 context.insert/stickerAssets.insert 又刻意包了 `await MainActor.run`——说明作者知道要回主线程，唯独漏了这三个 UI 状态字段。
风险：SwiftUI 从后台线程收到 observation 更新，属未定义行为（UI 不刷/偶发崩溃/runtime warning）。StickerImportSheet 的进度文案读的就是 importProgress。

**2. asyncAfter 闭包跨 0.5s 持有 @Model 实例** — `Views/StickerGestureOverlay.swift:372-379` — D3 — P2
现状：`DispatchQueue.main.asyncAfter(deadline: .now() + 0.5)` 闭包直接捕获 PlacedSticker @Model。
风险：与 StickerViewModel.swift:67-78 自己写的 "Profile Switch Race Defense" 相悖——切楼层后 0.5s 窗口内访问 sticker.id 就是该注释描述的 fatal 场景。窗口小但与已修过的 crash 同根。

**3. withCheckedContinuation 包 PHImageManager 有挂起/双恢复隐患** — `Views/PhotoStripPanel.swift:180-188` — D3 — P2
现状：`.opportunistic` 模式下回调可多次触发；若高清版本永远不来（iCloud 取图失败且只回了 degraded 帧），continuation 永不 resume，task 泄漏；协议上也没有"非 degraded 只回一次"的保证，双 resume 即崩。应改 `.highQualityFormat` 或加 resume-once 守卫。

**4. StickerStyleSheet 预览渲染无取消/无序号** — `Views/StickerStyleSheet.swift:209-235` — D3 — P2
现状：每次 selectedBorder/selectedFilter 变化都 Task.detached 跑全套滤镜+描边渲染，结果直接写 previewImage，无取消、无 generation token。
风险：连续快速点选样式时，慢的旧渲染可能后到，覆盖新选择的预览；同时多个 CoreImage 渲染并发占 GPU。

**5. Timer/observer 管理结论（重点核查项）**：宠物与花园动画**不用 Timer**，全部是 repeatForever SwiftUI 动画（CPU 影响归 D4）。FileLibraryPanelView（5s，:58-60）与 FileEditorSheet（4s，:883-885）的 Timer.publish 经 onReceive 绑定 view 生命周期，卸载即取消，**无泄漏**；但 publisher 写在 body 内联，body 重算会重建/重置计时器（轻微）。PagingViewController 的键盘 observer 在 deinit 移除（:149-151），ScrollableTerminalView 在 didMoveToWindow(nil) 移除（CCTerminalPanelView.swift:258-278），StickerViewModel 的 NotificationCenter observer 在 deinit 移除（:97-101）——均正确。

## D4 内存性能（重点）

**1. updateStyle 后图片缓存永不失效 → 全链路显示旧图** — `ViewModels/StickerViewModel.swift:363-372` + `Services/StickerFileManager.swift:28-36` — D4 — **P1**
现状：updateStyle 用**同名文件**覆盖写（`"\(id).png"`），但从不调 evictCache（全工程仅 deleteAsset 调过一次，已 grep 确认）；loadImageCached 的 key 是 `"\(profileId)/\(path)"`，不含内容版本。StickerView.loadImage 只在 .onAppear 跑一次（StickerView.swift:76-79），StickerThumbnailView 虽然 `.task(id:)` 会因样式变化重跑（StickerLibraryView.swift:304），但重跑后从缓存拿到的还是旧数据。
风险：改完描边/滤镜，库缩略图和画布贴纸在本次会话内一直显示旧样式，重启才恢复。修法：saveStickerImage 后 evict，或 key 掺入 mtime/版本号。

**2. 画布贴纸加载全尺寸原 PNG 而非缩略图** — `Views/StickerView.swift:159-177` — D4 — P2
现状：加载 `"\(assetId.uuidString).png"`（全尺寸抠图产物），显示却被 `.frame(maxWidth: 120)` 限制。NSCache 限的是 50MB 原始 Data，解码后的 NSImage/UIImage 不受 cost 限制。
风险：一屏多张大图贴纸时解码内存远超直觉。

**3. 壁纸图片在 body 里每次重算都从磁盘加载** — `Views/ThemeBackgroundView.swift:136-149, 178-185` — D4 — **P1**
现状：`NSImage(contentsOf: url)` / `UIImage(contentsOfFile:)`（无缓存 API）在 body 内执行；ThemeBackgroundArtwork 套在 GeometryReader 里且接收 canvasSize，macOS 主窗体背景就是它——窗口 resize 期间每个尺寸 tick 都触发磁盘重读 + 解码。
风险：拖拽改窗口大小时壁纸路径上持续 IO/解码 churn。应把解码结果缓存，key 为 url。（iOS 聊天主路径已迁去 PagingViewController 的 UIKit 层并有 lastImageURL 去重，:342-354，做法正确；这条主要打 macOS 与 iOS 设置预览。）

**4. 每次 renderBorder/applyFilter/liftSubject 都新建 CIContext** — `Services/StickerBorderRenderer.swift:59`、`Services/StickerFilterRenderer.swift:54`、`Services/SubjectLifter.swift:69` — D4 — P2
风险：CIContext 创建是重操作——批量导入 20 张图 = 40 个 context。同仓库 PagingViewController.swift:72 已写明"共享一个全局实例"并做了 sharedCIContext，三个渲染器应照搬。

**5. Theme token 每次访问全量重算 + UserDefaults 读** — `Utils/Theme.swift:9-24` + `Utils/ThemeManager.swift:317-330` — D4 — P2
现状：Theme.mainBg 等每次访问都走 currentTokenSet → resolvedTokenSet，含 UserDefaults bool 读和最多两次 token set 整体变换；一个 body 用 6 个色 = 6 次完整解析。themeChangeID 已存在但未用于 memo。
风险：聊天流式输出期间 body 高频重算，每个色读都叠加这份固定开销。

**6. 常驻 repeatForever 动画群** — D4 — P2
- `Views/MemoryPanelView.swift:611-618`：每张记忆卡 onAppear 起永久呼吸动画（3-7s 周期）；
- `Views/GardenSceneView.swift:38-41`：16 颗星 twinkle + 云 drift 作为新对话聊天背景全程跑；每朵热记忆花再各起 sway（:139-144）；

- `Views/DashboardView.swift:62-64`：wobble repeatForever 在 onAppear 无条件启动，与 editing 无关。
风险：装饰动画都有界（随 view 卸载停止，无泄漏），但叠加起来是 dashboard/聊天开场的持续 CPU/GPU 底噪。

**7. CalendarPanelView 每次 body 新建 DateFormatter** — `Views/CalendarPanelView.swift:284-296` — D4 — P2

**8. FileLibraryPanelView 主线程批量文件 IO + 轮询** — `Views/FileLibraryPanelView.swift:587-599, 568-575, 58-60` — D4 — P2
现状：reload() 同步在主线程为每个文件读 4KB 预览；每 5s checkForExternalChanges 在主线程列目录算指纹。
风险：文件多时打开文件库 tab 卡顿。预读应下沉后台。

**9. ThemeManager.persistDefinitions 每次 didSet 全量编码** — `Utils/ThemeManager.swift:50-67, 348-351` 配合 `:282-307` — D4 — P2
现状：背景透明度/偏移 slider 的每个 tick 都走全部主题 JSON encode + UserDefaults 写。应 debounce 持久化。

**10. WebView 生命周期** — `Views/Web/WebViewHost.swift:102-134, 164-178` — D4 — 未发现显著问题
coordinator 持 webView 为 weak，无保留环；latestPayloadJSON 字符串比对挡住重复注入。轻微点：每次 update 对全文做 JSONSerialization（大文件每击键一次），卸载时未 removeScriptMessageHandler（因无环不致漏）。

**11. DEBUG 探针在手势热路径做同步文件 IO** — `Utils/ProbeStickerSeed.swift:13-31` — D4 — P2（仅 DEBUG）
现状：PROBE 每次调用 NSLog + 打开 FileHandle 写 probe.log 再关闭；touchesMoved/handlePan 每帧调用。
风险：DEBUG 构建里贴纸拖拽体验与 Release 显著偏离，调性能时会误导。Release 已是 `@inline(__always)` 空 stub（:144-146），隔离正确。

## D7 macOS 适配

**1. 隐藏快捷键按钮常驻注册，含无修饰键 Delete/[/]** — `Views/StickerCanvasLayer.swift:122-178` — D7 — **P1**
现状：只要 StickerCanvasLayer 挂载（= 打开任何对话），五个隐形 Button 的 keyboardShortcut（⌘C/⌘V、无修饰键 ⌫、[、]）就参与窗口 key equivalent 链，未用 `stickerVM.isEditingStickers` 做条件挂载。
风险：(a) ⌘C/⌘V 在 performKeyEquivalent 阶段先于菜单栏被 view 链匹配，存在抢走聊天文本复制/输入框粘贴的风险；(b) 无修饰键的 ⌫、[、] 在"有贴纸选中 + 焦点在输入框"时可能把按键吃成删除贴纸/调图层。事件吞噬不依赖动作是否生效。建议至少包 `if stickerVM.isEditingStickers`，并实测 ⌘C 行为。

**2. 拖拽 payload 是裸 plain-text UUID** — `Views/StickerLibraryView.swift:301-303, 386-388`、`Views/StickerKeyboardPanel.swift:303` — D7 — P2
风险：macOS 上把贴纸拖进任何文本接收方会粘出一串 UUID 文本。自定义 UTType 可同时避免 DashboardView 的 widget 重排拖拽与贴纸拖拽互相误识别。

**3. NSCursor push/pop 不平衡** — `Views/StickerCanvasLayer.swift:544-548, 587-591` — D7 — P2
风险：hover 态下手柄消失（删除贴纸、按 Esc、点完成）不会触发 onHover(false)，光标滞留 resize/crosshair 形态。

**4. 右键菜单/多显示器**：贴纸画布、贴纸库、世界书、文件库、卡库的 contextMenu 覆盖完整；未发现多显示器相关坐标假设问题——**未发现显著问题**。
