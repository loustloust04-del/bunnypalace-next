统一编辑器：撤回不对 / 闪 —— 模拟器复现取证

2026-10-15 · 模拟器 9451D1D2（iPhone 17 Pro · iOS 26.4）· 装的是 master 13:15 版（markdown-editor.js 与 page2-apps 工位逐字节相同）· 只取证，未改代码 / 未装包 / 未 git 写操作

一句话结论

撤回不对和闪是同一个根因：Swift 回推的「旧回声」。网页每次把改动报给 Swift（打字停顿 180ms 防抖）后，Swift 会先推回一份「新 revision + 旧正文」，网页的守卫只丢 revision 更小 的回声，revision 相等就放行 → 刚打的那批字被删掉；5–18ms 后第二份「新 revision + 新正文」又把字插回来。

一删一插都不进撤销历史，结果是三件事同时坏：

  • 撤销历史被冲掉：用户刚做的那一步在 CodeMirror 历史里被映射成空、丢弃 → 浮条撤销按钮长期置灰点不动；⌘Z 撤到的是更早的步骤，甚至把「全选删除」前的旧文重新插回、拼成从没存在过的文本。重做在撤销后 180ms 被清零。
  • 光标跳回、打字乱序：光标被映射到这批字的开头，下一批字插在前面。按键间隔 ≥180ms 时逐字倒序（敲 abc 得 cba，敲 12345+abcde 得 1abcde5423）；中文拼音组字被打断，拼音字母原样落进正文。
  • 闪：每次停顿后 +180ms 出现一帧「旧布局」。改行数的操作最明显：回车 / 退格合并行时整屏上下跳一行（24px）再跳回；撤销时跳 150px。没看到整页闪白或渲染态/源码态来回切。

源码模式（UITextView）不走这条回声，打字和撤销都正常。打开文件后什么都不改直接撤销：正常（10-14 修的「撤成空白」没回归）。

根因证据（运行时探针日志）

方法：lldb 附加 App 进程，对编辑器 WKWebView 调 evaluateJavaScript，在页面里包一层 memoryPalaceNative.receive / post 记日志（只读埋点，关编辑器即失效，没碰源码）。下面是硬件键盘（HID）快速敲 xyz 的完整往返：

10609   dom   insertText "x"   head=17
10661   out   historyState     canUndo=true            ← 历史里有了这一步
10822   dom   insertText "z"   head=19
11006   out   contentChanged   rev=43  len=44          ← 网页 180ms 防抖后上报
11012   out   historyState     canUndo=false           ← 被下一行冲掉

11017   in    setContent       nRev=43 nLen=44  (新文)   head 17→17

第一条 setContent 带着已经更新的 revision 43 和还没更新的旧正文（41 字）。网页守卫 markdown-editor.js setEditorContent：if (nativeRevision !== null && nativeRevision < revision) return;——43 不小于 43，放行；minimalChange 把 xyz 删掉（addToHistory=false），光标从 20 映射到 17；3ms 后第二条把 xyz 插回，光标留在 17（插入点之前）。

Swift 侧来源：MarkdownWebEditorView.handleMessage 的 contentChanged 分支先 revision = newRevision（本视图 @State）再 content = newContent（父级 FileEditorSheet 的 @State 绑定）。实测 SwiftUI 先用「新 revision + 旧 content」跑了一次 updateUIView，WebViewHost 按 JSON 去重后照发；下一帧父级更新再发一次正确的。顺序并非每次都这样（偶尔是「旧 revision + 新正文」，那次被网页正确丢弃），但在本机几乎每次停顿都中。相关改动：8c7a4914c（10-14「revision 无论内容变没变都要跟上」）。

触发条件 / 修复方向（供车头参考）

  • 触发：实时模式下任何一次网页上报 contentChanged（= 停顿 ≥180ms）。软键盘、硬件键盘、粘贴、格式命令、撤销本身都会触发；连续快打（<180ms/键）整串只在停下时触发一次，所以快打时「看起来正常、停下那一刻光标跳回串首」。
  • 不受影响：源码模式；打开文件的首推（revision 0 → 网页也是 0，内容相同或首次载入）。
  • 方向（任选其一，未验证）：① 网页侧：nativeRevision === revision 时只接受与自己在该 revision 发出去的正文相同的内容（不同就丢）；Swift 自己改正文（源码模式 / 外部重载 / 版本恢复）时让 revision 前进。② Swift 侧：revision 与 content 放进同一个状态原子更新，或 revision 也放到父级与 content 一起改。修完回归点：本报告 #1–#5、#8、10a–10g，以及 10-14 修过的「撤成空白」（#6）。
