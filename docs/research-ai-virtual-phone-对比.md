# 对比研究：ai-virtual-phone × 记忆宫殿

- 日期：2026-09-10（pi-lane）
- 对象 A：**ai-virtual-phone**（下称 AVP），github.com/xiaolongbao0709/ai-virtual-phone，Next.js 15 + TS，浏览器/PWA，lib/ 约 280 个模块
- 对象 B：**记忆宫殿**（下称 MP），SwiftUI + SwiftData 原生，macOS 15+ / iOS 26+
- 问题：**MP 应该向 AVP 学什么**（粟粟钦定方向）

## 0. 定位差异（学习的前提）

AVP 是「仿真手机沉浸舱」：AI 住在手机里，主动找人、有作息、跨 App 有生活痕迹。MP 是「对话浏览器 + 受控聊天客户端」：树形分支、楼层隔离、可审计记忆。**AVP 的长处恰好是 MP 的空白带：主动性、生活感、跨模块联动。** 以下每条都附 AVP 实现位置 + 移植到 MP 的落点。

## 1. 全应用行为投影成统一「记忆时间线」★最值得学

**AVP 做法**（lib/short-term-assembler.ts）：不搞独立事件日志，而是把用户/角色在**所有模块**留下的原生数据——聊天、朋友圈、日记、VN、地图冒险、游戏、便签墙、查手机、共创——统一投影成一条时间线，直接作为记忆总结的素材（memory-summarizer 读它）和短期上下文。

**为什么值得学**：MP 的记忆提取目前只从聊天轮次来。但 MP 有 BookEntry / HealthLog / TradeEntry / Vocab 这些模块——用户在记账、在读书、在记健康，AI 全都不知道。「AI 记住你」的记忆素材应该 = 用户在 app 里的一切行为投影，不只是说了什么。

**MP 落点**：写一个 TimelineProjector，各模块产出统一投影条目（时间 + 来源 + 文本），喂给现有记忆提取管线。不动 Memory 模型本身，只拓宽上游。这也顺势回应记忆报告里「素材单一」的病。

## 2. 主动消息服务（follow-up / 定时唤醒 / 安静时段）

**AVP 做法**（lib/follow-up-service.ts，1100+ 行）：
- 后台服务独立于任何 UI 组件，3s 轮询调度表，用户不在聊天页角色也会发消息
- 三种触发：AI 主动追问（follow-up 调度）、定时唤醒（角色说"一小时后提醒你"→ LLM 自己设的闹钟，timed-wake-storage）、特殊关怀（如经期）
- 有安静时段（push quiet hours）、每会话取消、上限 10 条防刷屏
- **生成状态是服务级事实**：`backgroundGeneratingSessions` 集合，聊天室中途挂载时查它恢复「正在输入」，不靠事件重放补缝

**MP 落点**：楼层人格主动开口完全契合「AI 记住你」。macOS 侧定时器 + 我们已有的 PushNSE 推送扩展就能做 MVP：每会话 followUp 调度表 + 安静时段 + 用户发消息即取消。iOS 后台受限，先做 macOS。

## 3. 角色时区与作息感知

**AVP 做法**（lib/character-time.ts）：每个角色带时区字段，prompt 里注入双时间（系统时间 + 角色本地时间 + 星期），并明确指示「判断作息、问候、深夜/清晨优先用角色本地时间」。群聊时逐角色注入各自时间。

**MP 落点**：极低成本——角色卡加一个时区字段，PromptAssembler 注入时间上下文宏。问候语符合昼夜这种小事，是「它活着」的感知来源里性价比最高的一个。

## 4. 宏引擎：一切动态上下文都走统一宏通道

**AVP 做法**（lib/macro-engine.ts）：MacroEngine 暴露的变量面极细——`{{user}}` `{{char}}` 之外还有 followUpCount、currentSchedule、timeContext、customStickerNames、musicLocal、甚至经期关怀上下文。凡是会注入 prompt 的动态信息，一律做成宏，用户可在预设里自由编排。

**MP 对照**：我们有 Preset 插槽 + WorldBook + RegexScript，骨架相当，但宏变量面窄。**学习点不是再造引擎，而是原则：凡注入 prompt 的动态上下文，一律进宏注册表，不设例外通道。** 新功能想暴露上下文？注册一个宏，preset 作者自己玩。

## 5. 结构化回复协议：一条消息承载多种呈现

**AVP 做法**（lib/rich-message-parser.ts + offline-prompt-builder.ts）：
- AI 回复用 XML 包裹 `<thinking>/<content>/<summary>`，解析成 ParsedMessagePart 渲染富卡片（转账/红包/语音/生图）
- 思维链**按原标签拼回历史**，后续轮次上下文里保留思考内容
- 线下轮次（offline turns）重建成与线上**完全同构**的 ChatMessage[]，且「提示词预览器」与真实发送共用同一构造器——**预览 = 即将发出的真相**

**MP 落点**：我们已有 MessageSegment 的底子。可学的两点：① 结构化协议让一条 AI 消息不止文本气泡（卡片化呈现）；② prompt 预览与真实发送必须共用同一个 assembler——如果我们的调试面板是另拼的，就该合并。

## 6. 现实桥（远期，思路先行）

**AVP 做法**（lib/reality-bridge/）：角色可调用用户映射的 iPhone 快捷指令，文本/图片结果回传后**继续回复**——AI 从笼子里伸手碰真实设备。

**MP 落点**：iOS 侧用 Shortcuts URL scheme 可做同款。属于「AI 记住你 → AI 帮你办事」的进化方向，先记账，不进近期 roadmap。

## 7. 专题：桌面助手「小卷」有哪些可学

AVP 的小卷（lib/mascot-*.ts + components/mascot/，约 8000 行）不是聊天角色，是**元层创作助手**——帮用户写角色卡/世界书/预设/正则、改 CSS、处理图片素材。可学的六点：

### 7.1 「AI 帮你写配置」这个产品定位本身 ★
MP 有 CharacterCard / WorldBook / Preset / RegexScript 全套创作模型，但创作纯手动，门槛全在用户身上。「你控制它怎么说话」的短板不是控制力，是**控制需要专业技能**。一个会写预设/角色卡的助手正好补齐。「7 段式人设写作规范」（世界观四维度、表面人格三层，mascot-prompts.ts 共 813 行）这类 prompt 本身就是资产——把「会写卡的人的经验」固化成了 prompt。

### 7.2 分层 prompt 架构：人设 + 能力 + 页面上下文
System prompt = PERSONA（固定人设）+ CAPABILITIES（工具包清单）+ PAGE_PROMPT（页面专属规范）+ 当前状态。`MascotPageContext` 全局同步：用户逛到哪个页面，助手自动切对应 prompt 层、直接操作该页面的草稿。**助手知道你在哪、在改什么**——MP 做助手时，当前焦点模块（记忆页/预设页/对话页）就该是它的上下文输入。

### 7.3 双协议工具调用，一套 agent 循环两种线格式
mascot-engine.ts：provider 支持原生 tool calling 就走原生，不支持回退文本协议（XML 解析），引擎层同一循环。实战细节：Gemini 多轮工具调用必须把 reasoning 回传否则丢上下文、剥离 LLM 幻觉时间戳。MP 的 ProviderRouter 已有双协议底子，将来加 agentic 功能这是验证过的模式。

### 7.4 工具即「app 内部能力的 LLM 化」，参数联动靠硬约束
10 个工具包（CSS / 图像处理 / 角色卡 / 角色世界 / 世界书 / 预设 / 正则 / 状态栏 / 桌面组件 / 特调）把 app 内部操作整个暴露给 LLM。精彩的是**链式约束**：「生成九宫格CSS」的参数必须来自「校准九宫格」返回值，而校准是**弹窗让用户手动拖切线**——LLM 不猜参数，关键环节人介入。教训：LLM 干粗活，精确参数要么工具算、要么人校准，约束写死在工具描述里。

### 7.5 行为状态机写在 prompt 里，不写代码
「字段全空+用户描述→全量生成；有内容+要求改→只改对应字段；纯聊天→不出 action」——prompt 判断而不是代码分支。配合 action 式输出（每字段一个修改动作），局部编辑不整篇重写。

### 7.6 辅助 API 绑定：助手和主聊天分开配模型
小卷走独立的 `mascotApiConfigId` 辅助绑定——创作助手可用便宜/快的模型，不占主聊天通道。记忆总结、embedding 同理（AVP 全是辅助绑定制）。MP 做后台 LLM 任务时「辅助模型槽」概念直接拿。

## 8. 学不来的

PWA 零安装分发（一个 URL 就是产品）、浏览器里的玩法密度（应用市场 SDK、游戏大厅）。平台差异，认。

## 9. 优先级建议

| 项 | 成本 | 对「AI 记住你」的增益 | 建议 |
|---|---|---|---|
| 1 记忆时间线投影 | 中 | ★★★（治记忆素材单一的病） | 下个记忆模块 plan 的核心 |
| 2 主动消息 MVP | 中 | ★★★（从「应答」到「陪伴」的质变） | macOS 先做 |
| 3 角色时区 | 低 | ★★ | 顺手做 |
| 4 宏注册表原则 | 低 | ★★ | 作为编码原则立下来 |
| 5 结构化回复协议 | 中 | ★（呈现层） | 有富消息需求时再做 |
| 6 现实桥 | 高 | ★★（长期方向） | 记账 |

## 附：反向（MP 值得被学习的，存档备查）

树形对话（MessageNode 分支 vs 对方线性 session）、记忆可审计性设计（出处锚/软失效/反馈纠错/embedding 版本化）、楼层一等隔离、原生工程纪律（后台线程/token 预算/测试与发布通道）。详见本节 git 历史首版。
