## 一句话结论

**AUDN 记忆提取已停摆 11 天（最后一条 2026-06-26），根因是提取模型钉在家里局域网的"Mi"中转（`http://192.168.31.20:8792/v1`），人在宿务物理连不上，每轮提取静默超时。** 7 月以来她发了 ~4000 条消息，AI 一条都没记住。

## 证据链

### 1. 提取端：停摆

Air 真机 `ZMEMORY` 按创建日期分布：

| **06-27 至今** | **0** |

同期消息量（`ZMESSAGENODE`）：07-02 起每天 468/770/1074/868/505 条——**用得很凶，记得为零**。

### 2. 根因：提取模型不可达

真机 UserDefaults 实拉：

- `mem_master = true`，提取/注入开关全开，不是开关问题
- `memoryExtractModelId = "cred-45F68EB2-…/claude-sonnet-4-6"`
- 该 credential 名为 **"Mi"**，baseURL = **`http://192.168.31.20:8792/v1`** ← 家庭局域网地址
- 本机 curl 实测：`Connection timed out`（当前网络不可达）
- 时间线吻合：最后提取 06-26 → 06-28 出发香港 → 06-29 飞宿务

提取是 fire-and-forget，失败无任何 UI 反馈 → 静默死了 11 天没人发现。

**修复（粟粟自己就能点）**：设置 → 记忆 → 提取模型，换成 OpenRouter（🦊）或其他云端凭证。换完下一轮对话就恢复提取。

**产品债（要立项）**：提取连续失败 N 次应该在 UI 冒头（设置-记忆页红点/最后提取时间戳），否则这类静默死还会再来。另外提取模型允许配局域网地址本身没错（本地模型是合法场景），但"上次提取成功时间"必须可见。

## 对照 `上下文供应链关键文档/` 的对账（07-07 补，8 篇读完）

设计文档定义的体系（06-10~13 建成）：push 侧 M0-M8 全收官（RRF 融合 / BM25+向量 / 图谱 / BP1-4 cache / 画像 / 时间轴 / 开关化），pull 侧 B1 recall + 记忆树 v1（摘要迁文件 / memory/ 只读挂载 / hint pull 化 / 窗口锚定）+ B2 提取器（quote 锚 / superseded / NOOP）+ B3 目录注入 + B5 kiwi MCP（A 先行）+ B27。唯一未完批次 **B4 预算协调器**（刀3/刀4 done，刀1/2/5/6 留），gate = B0 验证残项在粟粟手里。

**对账结论：楼是盖好的，但两个活水口断了，外加三处开关面漂移。**

1. **上游断供**：提取模型 Mi 不可达（本报告主发现）→ 06-26 起原子记忆零新增 → M2/M3 检索无新料、M5 画像无料可聚、supersede 不再发生——全套 push/pull 机制在空转 44 条存量。
2. **验证债拖账**：B0 残项"M2 召回质量日用实测"（roadmap-context-supply-chain B0 第 2 条，06-13 就点名是 M3 解冻 gate）拖到 07-05 散步才拿到活样本（宿务 top-1）——设计文档预言要验的正是这一项。B4 因此继续搁浅。
3. **开关面漂移（真机 plist 实查 vs 设计默认）**：
   - `mem_supersede_soft = false`（plist 显式写了 false）——⧫ 06-12 批的是**默认开**（"可逆优于不可逆"），代码默认值也是 true（MemoryService.swift:236）。现在 AUDN delete = 硬删不可逆。是粟粟自己关的还是哪次设置事故写的，待确认。
   - `mem_content_timeline = false`（默认值没动）——**daily 日记停在 06-11 不是坏，是时间轴开关没开**。
   - `mem_content_heartvoice = true` 但心声只有 06-15/16 两篇——心声由 AI 自己调 `inner_voice` 工具触发（InnerVoice.swift:5-8），模型没调就没有，不算实锤故障；但若 F4 工具总开关关掉，inner_voice/recall 会一起消失，观察项。
