## 二、存储

### 2.1 文件夹

```
memory/wiki/
  INDEX.md                    根索引（代码生成，不手写）
  工程/INDEX.md               一层一份
  工程/项目/INDEX.md
  工程/项目/记忆宫殿.md        一页
  楼层/粟粟/身体.md
  楼层/人/小慧.md
  …
  .history/<页相对路径>/<yyyyMMdd-HHmmss>.md   「现在」每改一次存一版（整页快照）
  .proposals/<id>.json        整理提案（待批 / 已批 / 驳回，批完留 30 天再清）
  不触发的词.txt               她自己加的，一行一个
```

- 第二层往下的分组（人 / 项目 / 主题 / 粟粟…）由 C3 提、她能改。代码里**只写死**「工程 / 楼层」两支（规格第 1 节）。
- 页是普通 md，前面一小段 frontmatter：

```
---
类: 人            # 人 / 物 / 地点 / 时间 / 事 / 项目 / 主题
触发词: [小慧, 慧慧]
钩子: 她提到小慧、室友、合租的时候先看这页
---
# 小慧
> 钩子：…（和 frontmatter 同一句，给人读的）
## 现在
在吃二甲双胍（自 2026-09 起）。下周三复诊（到 2026-10-22）。
## 记录
- 2026-10-12 ……（出处：窗口《…》第 N 条）
- 2026-10-15 约了复诊（到 2026-10-22）（出处：…）
## 连到
- [[楼层/地点/五楼出租屋]] · 补充 · 一起住过
```

- 「现在」**每一句都标从哪天起成立**（规格 4⅞-1）：「（自 2026-09 起）」，精确到月或日，看原料给到哪。
- **带明确日子的事记有效期**（规格 4⅞-3）：「（到 2026-10-22）」。可以写在「现在」的句子上，也可以写在记录行上。过期了不删，第 ② 段注入时标「已过期」。
- 这两个标记都是正文里的固定写法，代码按这个格式解析，不另加字段。

- **索引由代码从页的 frontmatter 生成**，不让模型写索引：
  - 每次写页后重建受影响的那几层。
  - 一层超过 30 行时，不自动乱拆，下次 C3 跑时多出一种提案「分组调整」（把这层拆成几个子组），批了才挪。
  - 根索引只列两支 + 每支下一层的分组行：「楼层/人 — 她提到身边的人时（12 页）」。
  - 叶子层一行一页：「小慧 — 她提到小慧、室友…」。
- **「现在」历史**：
  - 写之前把整页旧版存进 `.history/`。
  - 页查看器加一个「历史」，能翻能恢复。恢复本身也存一版。
  - 「记录」只追加，代码里拦：提案里对「记录」只能追加行，不能改删。

### 2.2 碎片标记（`Memory` 加三个可选字段）

- `organizedAt: Date?`：整理过了。有两种情况：
  - 批了的提案用到了这条；

- `organizedPage: String?`：整理进了哪一页（wiki 相对路径）。
  - 空 + `organizedAt` 有值 = **单条就够**（规格 4⅝-1）：不进 wiki，留在池里照样能被召回，不算驳回。
  - 第 ② 段注入去重要用它（规格 4⅝-3）。
- `organizeRejectedAt: Date?`：驳回，不再自动整理。
- 轻量迁移，和上一刀的 `reviewedAt` 同一套路，同时补 `FullMemoryDocument` 镜像和导入。

## 三、A 线关键词搜（新服务 `ALineSearch`）

recall 现在是平的，C3 要的「A4 → A3 → A2」按关键词分层搜还不存在。这一刀新建一个**只读服务**，C3 用；召回侧那一刀以后直接拿它接 recall 的关键词兜底，这一刀**不改 recall 工具本身**，不动小克看到的东西。

- 输入：关键词（可多个，含别名）、楼层、时间范围（默认 10 月起不限）、上限。
- 顺序：
  1. 搜 A4 `timeline/*.md` 的条目行；
  2. 搜 A3 `windows/*.md`；
  3. 搜 A2 `sessions/*.md` 的段。
- 返回：每一处命中 = 层、日期、窗口号（A2 再加段号和消息起止）、命中那一段原文。A2 给整段（经过 + 原话），A4 / A3 给命中行前后一截。
- 上限（这一刀先写死，跑起来看花多少钱再调）：每个主题 A4 10 条 / A3 5 个窗口 / A2 8 段，总字数 6000 字封顶，超了先丢 A4 再丢 A3（A2 最有料）。
- 不搜原文消息：太大，A2 已经带原话；她要细节时小克自己翻。
- 纯文件读、不碰 SwiftData、不在主线程。老格式（旧 A4 大段、A2 第 0 段、老收尾段、v4-1 A3 抄本）照常搜，带「旧」标。

## 四、C3 写手（`CatalogOrganizer`）

### 4.1 一次整理怎么跑（两步）

**第一步 · 分拣（一次调用，便宜）**
- 喂给模型：
  - 根索引 + 各层索引（只有「标题 — 钩子」）；
  - 待整理碎片清单（id、正文、类别、日期）。
- 碎片范围：10 月起、没删、没整理、没驳回、不在待批提案里（⧫B）。
- 模型输出严格 JSON：每条碎片归到「已有页 X」或「新主题 Y（类、关键词）」，或者「**单条就够**」（规格 4⅝-1、`记忆系统v5.md` 1½「砖和平面图」）。单条就够 = 几乎不变、自己就完整的小事，比如「喜欢面包」。它不进 wiki，打 `organizedAt`、页留空，以后不再送分拣，留在池里照样能被召回，不算驳回。会变的状态（药、关系、项目进度）和跨很多天的事，要进页。提示词里把这张对照表原样写给模型。
- 没有待整理碎片的日子，自动那次连分拣都不跑（v5 1½「收敛」）。
- 代码按门槛过滤：新主题攒够 **3** 条碎片才进第二步；不够的留在池里等下次。点名的主题不受门槛。

**第二步 · 逐个主题写（每个主题一次调用）**
- 动笔前代码先备好材料：
  - 楼层提示词：从楼层人设 / 预设取她亲手写的那部分，取法照 `EffectiveCharacterContext`（⚠️ 具体取哪几段 implement 时核对，未查证）；
  - 这个主题相关的索引行 + 已有页全文；
  - `ALineSearch` 用主题关键词 + 别名搜回来的 A 线段落；
  - 这个主题分到的碎片。
- 提示词要点：
  - 照搬规格第 1–2 节的页格式；
  - 已有的事实不再写；
  - 有补充只追加「记录」；
  - 「现在」只在确有变化时改；每一句都标「（自 … 起）」（规格 4⅞-1）；
  - 新旧不一样，**先判「冲突」还是「共存」**（规格 4⅞-2）：
    - 共存（例：喜欢猫，也喜欢狗）两条都记，不连线；
    - 冲突（例：从五楼搬到了七楼）两条都留、各带日期，连一条「矛盾」，「现在」按新的写；
    - 判的是哪一种写进提案条目的「新旧判断」字段，审计台上显示出来；
  - 带明确日子的事标「（到 YYYY-MM-DD）」（规格 4⅞-3），相对日期（「下周三」）按原料的日期换算成具体日子；
  - 「事」类每节引用 A4 / A2 出处，不重抄经过；
  - 楼层提示词里已写过的不重复写；
  - 每一行记录都要带出处（碎片 id 或 A 线 层 / 窗口 / 段）。没出处的行代码直接扔掉。
- 输出严格 JSON，变成提案条目。格式不对时同一次调用里重试 ≤2 次（上次手搬的教训：输出先落盘再往下走，不整批重跑）。

上面两步**只给每天自动那次用**（规格 4½：便宜、稳、手机后台跑得完）。

### 4.1b 手动 = 真 agent（规格 4½，粟粟 10-17「手动的就要真agent」）

「整理一个主题…」和「现在整理」不走写死的两步，改成模型自己带工具循环。理由：只靠关键词会漏掉那天只说了片名、一句「电影」都没说的讨论。

- **循环**：照小芽（`AssistantEngine.swift:54,352-418`）的现成模式，模型出 toolCalls → 执行 → `ToolTurn` 回灌 → 下一轮，直到它交提案或轮数封顶。后端复用 `AssistantBackend`（云端走 `ProviderRouter` 原生 tool calling，选了本机模型也能走本机后端）。每一轮请求前都过一遍写入预算和全局预算闸，结束后记账（`UsageKind.catalog`），和 `modelCaller` 同一套检查；任何一轮被拦，就停下来，把已经搜到的东西交成一份「没整理完」的提案，不白花。
- **它能用的工具**（全部只读，最后一个是唯一出口）：
  - `search_aline(词[], 时间范围?)` → `ALineSearch` 的分层结果（A4 → A3 → A2，带层 / 窗口 / 段号）；
  - `read_aline(窗口, 段号?)` → 这个窗口的 A3 + A2 段目录；带段号就给这一段 A2 全文（经过 + 原话），读要窄；
  - `search_fragments(词[])` → 碎片池里没删的条目（id、正文、日期、状态）；
  - `list_wiki(路径?)` → 这一层索引；`read_wiki(路径)` → 一页全文；
  - `submit_proposal(条目[])` → 交提案（格式同 2.3）。交完循环就结束。
- **能顺着搜**：工具说明写明「搜到片名、人名、地名就再搜它」。第一轮的提示里给主题词，加上楼层提示词和根索引。
- **封顶**：每个主题最多 **N 轮**（⧫F = 10，已定；一轮可以同时调几个工具）。每次工具返回有字数上限（A 线一次 ≤6000 字），整个循环累计喂进去的工具结果 ≤40000 字，超了只能交提案。到顶还没交，就让它把手上的东西交成提案。
- **「整理一个主题…」**：一个 agent，跑这一个主题。已有这页就给它补，没有就新开（点名主题不受 3 条门槛管）。
- **「现在整理」**：⧫G 已定：先分拣一次，再每个主题各跑一个 agent。规格 E 的「最多 8 个主题」只管自动那次，手动不设主题上限，只受写入预算管。
- **随时能停**：「整理提案」格顶上显示「正在整理：电影（第 3 轮）」，旁边一个「停」。停了就不再发请求。已经写出来的条目交成一份「没整理完」的提案，不想要就在审计台整批驳回。
- **过程留痕**：每一轮调了什么、搜回多少，都写进记忆日志，提案详情里能展开「它搜了什么」。
- 交上来的提案同样要过 4.1 的检查：每行要有出处，「记录」只追加，关系只有四种。

### 4.2 什么时候跑

- **手动**：
  - 审计台「整理提案」那一格顶上「现在整理」；
  - 旁边「整理一个主题…」，输入框填词。
- **每天**（⧫A）：
  - 推荐「每天过了 05:00，花园第一次在前台（或 mac 一直开着到 05:00）就跑一次」。
  - 记下当天跑过的日子，不重跑。
- 都受写入预算管：
  - 新增 `UsageKind.catalog`，加进写入预算统计；
  - 走 `modelCaller` 同一条链（预算 → 全局闸 → 请求 → 记账）；
  - 预算超了这次不跑，记忆日志记一行。
- 每天自动那次最多整理 **8** 个主题（⧫E，已定），剩下的下次。手动不限主题数（见 4.1b）。
- 同一楼层同一时间只跑一个（actor 锁），手动和自动也互斥：自动正在跑时点手动，就排在它后面。她在聊天时照常跑：只读文件、只写提案，不碰正在写的 A2。
