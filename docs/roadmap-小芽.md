来源：粟粟 09-27「所以小芽的功能现在全了吗？还有哪些行为人类可做小芽不能做」→「按你推荐，现在先写 roadmap，4 小时之后开始」。
现状盘点（17 个工具，能读 / 能提案改什么、缺什么）见本文 §1；v3 收尾见 [review-小芽-v3](review-小芽-v3.md)。

## 0. 不变的规矩

- **写 = 提案**：一律走 `propose_` 工具 → 带类型的 `AssistantChange` → 她盖章才落地（唯一闸门 `stamp`）→ 进账本能撤（撤不干净的改动不开放）。
- **读不用盖章**，但读的范围也按权限包管（包关了，模型连工具都看不见）。
- **每个新工具都要过本机模型**：在 Mac 上用 1.7B / 4B 各跑 ≥5 次，调用成功率达标才上；同时补进本机的关键词分组（`AssistantTools.localGroups`），不然本机要么看不见、要么挂全部工具变慢。
- **每阶段走三步**：research → plan（她 ⧫ 批注，说 go 才动）→ 实现 → review 文档 → 装 Air 她验。

## 2. 阶段

### R1 记忆写入（先做）

她最常用、离「助手」身份最近的缺口。

- 工具：`propose_add_memory` / `propose_update_memory` / `propose_forget_memory`，可能加 `propose_pin_memory`。
- 撤销：记忆已有 `supersededAt`（版本链）——「改」和「忘」都做成新版本 / 标记失效，不硬删，撤销 = 恢复上一版。research 要核实这条链在衰减引擎、注入、记忆页里是不是都认。
- 顺手还债：`query_memories` 改成 SQLite 谓词查询（现在全量 fetch 再过滤）。
- research 要回答：`Memory` 的字段和来源标记；记忆页手动编辑走哪条路（复用它，不另写）；楼层隔离（profileId）；每轮自动提取会不会把小芽刚写的又抽一遍、或覆盖掉；现状病灶（[report-记忆现状](report-记忆现状-2026-07-07.md)）哪些会咬到。
- 待她拍板：要不要单独一个「记忆」权限包，默认开还是关。

### R2 已有三块补全

提案 → 盖章 → 撤销的流程直接套，改动小。

- 角色卡：删卡（撤销 = 整张快照恢复，含头像数据）、复制。换头像要选图，先不做。
- 预设：插槽开关 / 新增 / 删除 / 排序（撤销 = 整份插槽列表快照）。
- 世界书：新建整本、删整本（快照恢复）、改名。挂到楼层属于楼层配置，不做。
- 删除类工具在本机模式**不追加**「细节自己编」（v3 复盘 §2）。

### R3 只读看对话

只读、不盖章，风险低，但涉及隐私范围。

- 工具：`search_conversations`（走 S5 刚合进来的全文索引，不碰 MessageNode 全量 fetch）、`read_conversation`（按段取、限字数）、`list_recent_conversations`。
- 用途：「上周我跟 XX 聊过什么」「帮我把这个对话总结成一条记忆」（和 R1 连起来）。
- 待她拍板：默认能不能看所有楼层的对话，还是只看当前楼层；这个包默认开不开。

### R4 全局外观

- 主题（在现有主题里选）、字体、字号；提案卡里带试穿预览（复用 P3 的做法）。
- 待她拍板：只许在现成主题里选，还是允许她调颜色做新主题。
