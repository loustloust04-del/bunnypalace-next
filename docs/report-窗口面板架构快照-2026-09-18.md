## 1. 平台适配现状

### 支持哪些平台

**三个平台，两个 app target，一份源码目录。**

| target | platform | deployment target | bundle id | 设备 |
|---|---|---|---|---|
| `MemoryPalace` | macOS | **macOS 15.0** | `com.susu.MemoryPalace` | Mac |
| `MemoryPalaceIOS` | iOS | **iOS 26.0** | `com.susu.MemoryPalace.ios` | `TARGETED_DEVICE_FAMILY: "1,2"` = iPhone + iPad |

两个 target 的 `sources` 都指向同一个 `MemoryPalace/` 目录（各自 exclude 掉对方的 Info.plist）。**没有 iPad 专属 target**——iPad 跑的就是 iOS target 的包。

另外三个非 app target：`MemoryPalacePushNSE`（推送扩展）、`MemoryPalaceWidget`（小组件）、`StickerProbeUITests` / `MemoryPalaceTests`。

### Mac Catalyst

**没有。纯 native SwiftUI 双 target。**

- `project.yml` / `Info-iOS.plist` 里 `Catalyst` / `SUPPORTS_MACCATALYST` / `UIKitForMac` **零命中**。
- mac target 是独立的 `platform: macOS` 应用，走 AppKit 底座（`NSApplicationDelegateAdaptor` + `NSViewRepresentable` 配窗口）。
- 平台差异靠 `#if os(macOS)` / `#if os(iOS)` 在同一份 Swift 文件里分叉，不靠 Catalyst 的兼容层。

### iPad 的 multitasking / Split View / Stage Manager

**没有主动适配，但也没有禁用——系统默认全开，代码靠"量到多宽"被动跟随。**

具体：
- `Info-iOS.plist` 里**没有** `UIRequiresFullScreen`、**没有** `UIApplicationSceneManifest`、**没有** `UIApplicationSupportsMultipleScenes`（`plutil -p` 全量键已核）。
  - 没有 `UIRequiresFullScreen` → **Split View / Slide Over / Stage Manager 系统默认允许**，用户可以把 MP 拖成半屏。
  - 没有 `UIApplicationSupportsMultipleScenes` → 默认 `false`，**Stage Manager 下开不出第二扇 MP 窗口**，只能一扇窗改大小。
- 代码层的响应方式是**纯尺寸驱动**，不读 `horizontalSizeClass`、不读 `userInterfaceIdiom`：
  - `ContentView.swift:691` — `let wide = size.width >= Theme.landscapePanelThreshold`，阈值 **1100pt**（`Theme.swift:91`）。宽 ≥1100 进「宽屏面板形态」（跟 mac 同一套 `IPadPanelOverlay`），否则退回 iPhone 那套三页横滑。
  - 全项目 `horizontalSizeClass` / `userInterfaceIdiom` 只有 **1 处**命中（`Page2CornerBar.swift:154`，调一个 padding 数），不参与布局分叉。
- 代码里**明确写过 Split View**，说明是被考虑过的：
  - `ContentView.swift:680,689` — `panelLayout.screenSize = UIScreen.main.bounds.size`，注释「桌面格子按机器的屏幕档取尺寸（**Split View 缩窗不换档**）」。
  - `DesktopGridStore.swift:4` — 「存过的项临时放不下（键盘 / **Split View** / 转屏把格子压少）只是暂时不显示，存档不动，尺寸回来它就回来」。
- 支持的方向：iPad 四向全开，iPhone 竖 + 左右横（`project.yml` `INFOPLIST_KEY_UISupportedInterfaceOrientations_*`）。

> 一句话：**Split View 能用且不会崩**（布局按量到的宽退档、存档不丢），但没有为它做过验收；Stage Manager 多窗口**做不到**（缺 scene manifest）。

**看的文件**：`project.yml`、`MemoryPalace/Info-iOS.plist`、`MemoryPalace/Views/ContentView.swift`、`MemoryPalace/Utils/Theme.swift`、`MemoryPalace/Services/DesktopGridStore.swift`

## 2. 当前窗口管理

### 主窗口结构

**不是 `NavigationSplitView`，不是单一 `NavigationStack`——是自绘的四槽壳。**

`NavigationSplitView` 全项目只有 **1 处**命中：`MemoryPalace/Views/SettingsView.swift`（设置窗内部的六组目录 + 详情）。主窗一处没用。

Scene 层（`MemoryPalaceApp.swift:844`）：

```
WindowGroup { ContentView() … }          // 唯一主窗，两端共用
  .windowStyle(.automatic)                          :981
  .windowToolbarStyle(.unified(showsTitle: false))  :982
  .commands { … }                                   :983
#if os(macOS)
Window("记忆花园 帮助", id: "manual") { … }          :1040  .defaultSize(900×680)
Settings { SettingsView() … }                       :1048  .defaultSize(860×600)
#endif
```

主窗内部（`ContentView.swift:127` `body` → `:1654` `macLayout` / `:615` `iOSLayout`）：

**mac（含 iPad 宽屏）两棵树按 `panelLayout.mode` 切**（`ContentView.swift:1654-1662`）：

| mode | 树 | 形状 |
|---|---|---|
| `.docked`（全屏，**默认**） | `macDockedTree` `:1756` | `VStack { 标题行; GeometryReader{ 工作区 } }`，工作区里**四列并排实占**：`[dock][列表 或 左空地][正文卡][工具面板 或 右空地]` |
| `.floating`（窗口） | `macFloatingTree` `:1703` | `ZStack`：正文在底层按格子道让位（`DockedInsetHost`），面板 / dock / 浮窗盖在 overlay |

四槽几何的唯一所有者是 **`MacShellFrame`**（`Views/iPad/MacShellFrame.swift`，150 行纯函数，不读窗口不读单例，测试显式传参）。恒等式 `dock + 左 + 卡 + 右 == 窗宽` 有机器证明（`MacShellFrameTests.testFourSlotsAlwaysAddUpToWidth`）。

**iOS 窄屏**（`iOSLayout` `:615`）：三页横滑分页（列表 / 聊天 / Page2 桌面），走 `injectPagingEnv` + 自绘分页容器，不是 NavigationStack。

`NavigationStack` 全项目 97 处命中，但都在**子页面内部**（设置子页、工具面板内的详情推栈等），主壳一处没有。

### 浮动窗口 / secondary window / NSPanel

| 东西 | 是什么 | 实现 |
|---|---|---|
| **面板浮窗**（工具从 tab 组浮出来，可拖可缩可叠） | **不是系统窗口** | 纯 SwiftUI 自绘：`Views/iPad/FloatingWindow.swift`，画在 `IPadPanelOverlay` 的 ZStack 里，层级靠 `IPadPanelLayout.zOrder` 数组 |
| **设置窗** | 真 secondary window | SwiftUI `Settings` scene（⌘, 系统挂），mac only |
| **帮助窗** | 真 secondary window | SwiftUI `Window(id: "manual")`，mac only |
| **终端新窗**（`PixelTerminalHeader.swift:319-336` 的「新建终端/CC/Codex 窗口」） | **不是 MP 的窗** | 走 `CCBridgeWebSocketClient.openWindow(engine:)` → cc-bridge hub 在**系统终端/tmux** 里开，MP 这边只发指令 |

**`NSPanel`：零命中。`NSWindow` 只有 2 处**，都是配置不是创建：
- `MemoryPalaceApp.swift:1889` `WindowConfigurator.configure(_:)` — 透明标题栏 / `titleVisibility = .hidden` / `.fullSizeContentView` / 背景色 / 去分隔线
- `MacShellMetrics.swift:217` `measure(_ window:)` — 量红绿灯那一排的真实高度（不写死）

**多窗口能力：没有。** `openWindow` 只用于 `id: "manual"` 那一扇；主 `WindowGroup` 没有 `handlesExternalEvents`、没有多实例路由。roadmap 里 **A4「多窗口（去单例、每 NSWindow 一份 layout、`FocusedValue`）」是排队项，没开工**——现在 `IPadPanelLayout.shared` 是全局单例，两扇主窗会共享同一份布局状态。

### sidebar 怎么实现，可折叠吗

**可折叠，自绘，不是系统 sidebar。**

- 内容：`SidebarView`（`ContentView.swift:1798` `macSidebar` 包装）——对话列表 + 收藏 / 回收站 / **Code 组**（编程会话）+ 楼层切换 + 底栏。
- 宿主：作为 `IPadPanelOverlay` 的 trailing closure 传进去，渲染在四槽的「列表槽」里（docked）或一扇浮窗里（floating）。
- 折叠开关：`IPadPanelLayout.leftShown`（`:88`）。toggle 在 `ContentView.swift:992`，选中对话后自动收起在 `:984 collapseLeftPanelAfterSelect()`。
- 宽度：`leftWidth`（默认 320），渲染时按窗宽钳（`MacShellFrame.convWidth`，下限 240 上限 `maxPanelWidth`）。
- 菜单项：`CommandGroup(after: .sidebar)`（`MemoryPalaceApp.swift:988`），`⌥⌘S`。

### macOS / iOS 的条件编译分叉

**有，且是主要手段。** 关键分布：

- `ContentView.swift`（1919 行）：`body` 里 `#if os(macOS) macLayout #endif` / `#if os(iOS) iOSLayout #endif`（`:217-232`）。往下 mac 独占 `:1654-1919`，iOS 独占 `:615-1650`。

## 4. 状态持久化

### 窗口大小 / 位置

**app 自己没存，靠系统。**

- 主 `WindowGroup` 没有 `.defaultSize`、没有 `.defaultPosition`、**没有 `setFrameAutosaveName` / `frameAutosaveName`**（全项目零命中）。
- 只钉了下限：`ContentView` 上 `.frame(minWidth: 980, minHeight: 600)`（`MemoryPalaceApp.swift:869`）。
- 实际靠 **macOS 对 SwiftUI scene 的自动 window restoration**（系统写在 app 的 saved state 里，不在我们的 UserDefaults）。
- 两扇 secondary window 有 `.defaultSize`：帮助 900×680、设置 860×600。

### sidebar 展开 / 折叠

**存了。**和整套面板状态一起，一个 JSON 塞进 UserDefaults。

`IPadPanelLayout`（`Views/iPad/IPadPanelLayout.swift:181-225`）：
- key：**`"ipad.panel.layout.v2"`**，`JSONEncoder` 编码一个 `Snapshot` struct
- 写入时机：每个字段的 `didSet { save() }`（`:85-122`）
- 存的字段：`mode` / **`leftShown`** / `dockShown` / `leftWidth` / `rightWidth` / **`toolWidth`** / `openTools` / `selectedTool` / `detached` / `minimized` / `minimizedFrom` / `snapToEdges` / `frames`（每扇浮窗的 x/y/w/h）/ `zOrder` / `arrangement` / `dockSide` / `tabGroupCollapsed`
- **不存的（瞬态）**：`snapGuides` / `flights` / `screenSize` / mac 的 `macTabFrames` `macCardFrame` `macFlightTargets` `macDropTarget`
- 注入点：`init(defaults:)` 可注 suite，测试不污染 `.standard`

### 其它布局相关的存档

| 存的东西 | 机制 | key |
|---|---|---|
| 面板全套状态（见上） | UserDefaults + JSON | `ipad.panel.layout.v2` |
| 桌面格子里谁在哪一格 | UserDefaults + JSON（`Services/DesktopGridStore.swift`） | `ipad.desktop.placements.v1`（+ 迁移标记 `…laneDecoupleMigrated`） |
| 桌面上有哪些 app / dock 成员和顺序 | UserDefaults 字符串数组（`Services/Page2DesktopManager.swift:11-12`） | `page2DesktopApps_v1` / `page2DockTools_v1` |
| mac 壳的 18 根活参数（卡边距 / 圆角 / 标题栏高 / dock 格…） | UserDefaults 逐键 Double（`MacShellMetrics.swift:130-149`） | `前缀 + knob.rawValue` |
| iOS Page2 当前停在哪个 app / 开了哪些 / 在读哪本 | **`@SceneStorage`**（全项目仅这 3 处） | `page2.currentApp` / `page2.openApps` / `page2.readingBook` |

`@AppStorage` 全项目 **299 处**，但**没有一处存壳/面板布局**——全是功能偏好（字号、主题、导出模式、各工具自己的排序视图模式等）。壳的状态一律走 `IPadPanelLayout` / `DesktopGridStore` 那两个 `@Observable` 单例。

### SwiftData model 里有没有 UI layout 相关的 entity

**没有。** 23 个 `@Model`，逐个看：

`Conversation` / `MessageNode` / `ConversationTag` / `FavoriteItem` / `Memory` / `MemoryNote` / `WorldBook` / `UserCard` / `ImportRecord` / `ImportConversationChange` / `BookEntry` / `AudiobookItem` / `AudiobookBookmark` / `VocabProgress` / `TradeEntry` / `TickerEntry` / `WeightEntry` / `CycleDay` / `IntimacyEntry` / `Medication` / `MedicationLog` / `StickerAsset` / `PlacedSticker`

唯一带坐标的是 **`PlacedSticker`**——但那是贴纸在**聊天画布内容**里的位置，不是壳/面板布局。

**所有壳状态都在 UserDefaults，一条都不在 SwiftData。** 这意味着：
- 壳布局**不跟楼层（profile）走**——切楼层 `ContentView` 整棵重建，但面板开关 / 宽度 / 格子位置是全局一份。
- 壳布局**不进 iCloud、不进备份导出**。

### 其它硬约束（写在代码注释里的）

- `IPadPanelLayout` 的字段**必须平铺，不能收进 struct**（`:9-16`）——`@Observable` 按属性追踪，收进 struct 会让拖宽度时 `ContentView.body` 整棵重算（真机探针验过）。
- `MacShellFrame` 是停靠壳几何的**唯一入口**，小样 `docs/design-mac-fullscreen-otty.html` 的 `layout()` 是它的 JS 版，**改一处改两处**。
- 工作区尺寸**必须用 `GeometryReader`**，不能用 ZStack 里的 `Color.clear` 探针——固定宽的 HStack 兄弟会在缩窗那一帧撑大容器，探针量到旧数，缩不回去（09-17 实拍复现，`review-mac-fullscreen-shell-v2.md` §1）。
- `IPadPanelLayout.shared` 是**全局单例** → 多窗口（A4）的前置就是拆掉它。
