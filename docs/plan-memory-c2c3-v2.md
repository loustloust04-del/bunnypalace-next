6. covered-only 用最小「确认已覆盖」内容项承接，仍第二批批准才标；不为凑可批条目改假正文。单条就够沿现有 organizedAt+空page 标记留池，可召回、不是驳回，不造新状态；原有单条可由新增事实重新参与主题聚合，不把它当永远不能归页。方向拒绝不连带驳回线索碎片；具体内容拒绝沿原规格。
7. 复用楼层锁、取消、预算、.runs 和提案已处理状态，重复批准不能再次付费；待批占用只排同一批线索，不冻结无关主题。批准失败/停止记清结果，不加自动重试/恢复队列。种子目录复用这批法，但等第 6 段的同任务续跑，不套日常逐主题派发。

| 写模块结果 | 第二批 | 标记与后续 |
|---|---|---|
| 有正文变更 | 要 | 未批不改；批后标已整理，具体驳回按规格。 |

**旧数据怎么办**：非种子旧具体内容提案继续当第二批审，不补方向或自动重写；旧种子不是此保留策略，在第 6 段全清。旧 wiki/历史不迁移，日志不硬补两阶段。

**影响文件**：WikiProposal/Display/Views、CatalogRunner/Sorter/Agent、C3 工具定义注册与聊天分发。

### 第 5 段 · 种子前置：文件库「Prompt」与 Prompt 页同一份数据

**现状**：预设使用 PresetManager 的楼层实例，插槽不在 CatalogFloorPrompt 那五段里；文件库目前没有与「记忆」平级、双向编辑同源的 Prompt 根。现有通用文件编辑入口需要加数据路由，不是往磁盘复制 prompt 文本。

**实现**

1. 新增按 profileId 隔离的虚拟根「Prompt」，与「记忆」平级；列表取**该楼层当前 presetId 且 ownerProfileId 匹配的实例**，按 `SlotOrder.ordered(preset.prompts)` 保留 Prompt 页顺序，不走通用文件名/时间排序。`profileId + presetId + slotId` 作稳定身份；缺实例时不回退修改共享模板。
2. 一个插槽一个虚拟文本文件，显示文件名原样等于 slot.name，正文原样取 slot.content（包括空槽、关闭槽）；两边保存都修改同一实例，不复制到磁盘。文件库用现有 `FileEditorSheet.text`，保存重读实例/按 slotId 定位，只改本次正文，使用已有可抛错 `PresetManager.persistNew` 同 id 持久更新，写盘成功才更新界面；不沿 save 的吞错路径假报成功。Prompt 页观察同一实例更新，未编辑草稿刷新，保存只提交确实改过的槽，不能拿旧五栏快照覆盖别处新改的槽。
3. marker 文件只暴露它实际存储的 content，不把自动展开的 memory/历史/世界书灌回槽。`characterFormat / scenarioFormat / personaFormat` 三份格式模板**不放进来**（已定 15）；旧楼层仍在 Profile 的手填文字在「Prompt/楼层字段」映射真实字段（含角色性格、对话示例等），保存走原楼层字段持久入口。这些也是同源虚拟条目，不复制、不用截字预览。采样、开关、角色/深度/位置、rawJSONData 等非文字设置不导出。
4. 给 CatalogRunner 注入现有 PresetManager，在 MainActor 上从上述源取不可变完整底图：槽按 Prompt 页顺序全收；系统/身份/角色描述/场景等沿现有“显式槽优先、Profile 原文兜底”的字段路由，角色性格等无独立槽的原文完整保留；三份格式模板不纳入。每份记录真实槽/字段来源，不跨槽去重，不把未启用文字丢掉，不调用 PromptAssembler 或 TavernSync.cardFieldPreview。
5. 重名、空名、含斜杠的槽仍保留原显示名，内部虚拟路径用 presetId/slotId（楼层字段用稳定属性键），不用槽名拼真文件路径；空显示名可在副标题标未命名，不写回。种子用目录返回的稳定路径读，不手拼名字；改名不改变身份。
6. 文件库只补虚拟目录/读写/变化观察，复用现有文本编辑器，不改查看器性能实现；完整底图保留原顺序和来源、沿已有名字宏展开，不做 3000 字截断。日常与种子都读完整底图，后续写作分别用增量/种子规则。旧系统如果还是本机 caller 的 trimmed，不能以取值完整冒充请求完整；seed 直接走不截断的 agent backend，实际上下文错误原文返回，不自动换模型。
7. 备份继续保存真实 Preset/Profile 等数据，不保存虚拟副本；恢复后自动重建。主聊天 fs 若访问新增 Prompt，仍走原文件库授权与此适配，不因 seed 获得额外权限；seed 对 Prompt 只读。

**旧数据怎么办**：不搬迁/复制插槽，不改变旧 presetId/slotId、顺序、content、采样/开关。若旧楼层还指模板，走既有实例化入口再允许编辑，不直接写共享模板；保存失败不假显示成功，删除/切换槽后不能拿旧文件引用改另一个槽。

**验收**：楼层 A 的自建槽在五段之外、尾部超过 3000 字，文件库和 Prompt 页两边编辑均立即看到同一内容，重启仍一致；楼层 B/全局模板完全不变。槽顺序与 Prompt 页一致，重名、含分隔符、关闭槽、marker 对应字段、切换预设、保存失败各走实际 UI；采样/开关不出现在文件列表。备份恢复后同源显示，不产生第二份 prompt 文件。

**影响文件**：`MemoryPalaceApp.swift` 的 PresetManager/Runner 注入、`Models/Preset.swift`/`SlotOrder.swift`（复用数据）、PersonaSettingsTab 的文字编辑接点、FileLibraryPanelView/虚拟路径和列表路由、CatalogFloorPrompt/CatalogRunner；不创建 prompt 镜像目录。

### 第 6 段 · P3 种子：清旧产物，从 0 跑一个 agent，目录与正文两批

**现状**：旧种子按文件标题组 topic、包装随机 UUID 的 CatalogFragment，再逐主题走 material 搜 A 线/写手；旧完成只证明交过内容提案，不证明 wiki 入库。当前 agent 是单次运行，等审批后的持续任务、受限文件写入、待批草稿可视化都必须在本段补齐，不能写成已有。

**实现**

**A. 先备份，再删旧种子产物（从简，已定 16）**

1. 在**目标楼层**暂停种子及相关审批写入，同时与 CatalogLock 和现有审批锁互斥；清理范围只有三类：旧 `wiki/.proposals/.seed-state.json`、所有 origin=seed 的旧提案（任何状态）、由 origin=seed 提案**新建**的页（连专属历史）。不清空整个 wiki，不碰 CC 原料、Prompt、非种子提案、非种子 wiki。
2. 认定只看提案自身记录（origin=seed + 该项是新建页）；不追查 regroup 挪页链，不靠标题 / 目录像不像判断。
3. 旧种子若**改过**已有的非种子页：不自动回滚、不动那页，只在清理结果里列出「这几页被旧种子改过」给粟粟看，由她自己决定。
4. 复用 `MemoryRegeneration.makeBackup` 的搬迁约定，把目标楼层 wiki（含隐藏的提案、状态、历史、整理记录）完整备份到 **memory 旁「记忆备份」**；`.partial-*` 暂存，逐文件大小/SHA256 校验、manifest 成功后才发布正式目录，再 verify。清理清单随备份保存；任一步失败，删除数必须为零。备份是私人数据，不放 git、不进种子读源。
5. 备份成功后删除上面三类，保留非种子数据；从保留下来的页重建相关索引，去掉指向已删页的生成索引/连线残项，不借机自动合并/清库。旧 .runs 留作备份和诊断证据，不让它们当新种子原料。清理失败展示具体项，不写「已清空」或新完成时间。
6. 删除 CatalogSeed.topics、随机 f UUID 包装、旧 seed→material 搜索→逐主题 write 路径；界面不再被旧完成时间拦住。执行是本轮明确从 0 重跑，不保留「旧种子不自动重播」策略，也不让新旧路径并存。

**B. 一个 CatalogAgent 任务，全读一次，不走搜索流水线**

7. 保留现有 CC 种子入口，新增「从人设生成基础 wiki」设置入口（已定 15 保留），均发起一个 seed 模式任务，绑定发起楼层、所选 C3 模型及本次目录；这两个入口共用同一材料/目录/正文机制，不是两个提取流水线。原料域是本楼层 **Prompt 全部手填文本、CC user/project 合格文件、现有 wiki 正文与索引**，由文件工具每份完整读一次；没有某类原料就记不存在，不凭空补。
8. CC 先按文件名排 private_，根本不读，只记跳过数量；沿 CatalogSeed user/project 类型与日记排除逻辑，feedback 不交给模型作事实源。原料正文里的祈使句/回复规矩、人设指令也不进 wiki，不能以 user 类型就全当事实。
9. 使用现有 CatalogAgent 循环和 Deps/backend，不带小克 prompt，不调用 CatalogSorter、不用 search_aline/search_fragments、不按主题新建 agent、不先中模型抽事实。保留完整已读文本和来源/版本，目录后写页继续用这份已读材料，不重新读一遍、更不偷换已审原料。
10. **无人工原料上限**：不设总字符/文件/页数阈值，不把日常 resultLimit/maxToolChars/单主题 10 轮或本机 trimmed 搬进 seed；文件回执全量进入同一任务上下文，不能静默截尾、自动摘要、分批总结、主题检索替代或换模型。沿真实 backend 发完整请求。实际 provider（含本机后端）报上下文太长时，显示「这次完整种子材料超出当前模型上下文，尚未完成」，附错误原文/轮次/模型；不伪造内容、不记完成。种子不查、不扣日常写入预算（已定 14）；用户停止照现有规则。

**C. 工具最少，写权限只在待批区**

11. 选择更少工具的**复用文件 read + 现有 submit_proposal（outline/page 两个阶段）**，不开放通用 write/edit，不造「搜种子/提事实/按类写页」工具群，也不引入 bash。read 沿现有底层完整文件读，限定本次 Prompt/CC/wiki 白名单；submit 通过宿主原子保存目录/页内容到 `memory/wiki/.proposals/<本次id>/` 待批区。agent 的写能力只限这两个待批出口，不能指定正式工程/楼层页、INDEX、历史、状态文件或其他任务草稿为写入落点。
12. **不改小克 FileLibraryTools 的 memory 只读规则**。submit_proposal 只加最小 phase、目录项 id 和既有内容字段，不另造两个工具/审批库。taskId 复用目录提案 UUID；宿主保存成功后才给成功回执，同目录项重复交回已有提案，不重新收费/落重份。

**D. 先批目录，再同一个 agent 逐页写，再批正文**

15. 目录批完或分次批时，只写获批项。复用同任务的 history/turns/已读来源快照与页版本，从暂停点继续，不按页创建新的 agent 或专门 Writer 调用。逐页用 phase=page 交内容提案并显示页草稿；该页正文不必先批，agent 可继续下一获批页。目录改了则按改后的目标/原料执行，未批/驳回项不写。
16. 在本次待批目录保存现有会话的必要 checkpoint：任务/楼层、完整 history/turns/provider 内容块、已读来源/版本、目录关系和每页内容提案 id，复用任务文件，不做通用调度器；工具内容块用小型持久 DTO，不能直接假定 Codable。目录交审后暂停、批准动作恢复同一任务，继续同一 `.runs` 文件和轮号，审批反馈只作控制消息不作事实来源。不阻塞 UI、不长持锁等批，执行重取楼层锁；提交提案及 checkpoint 均成功后才回成功，不自动失败重跑。
17. 种子可以重述人设事实，不做底图重合去重、不只写空架子；事实与规矩分离。页用已有 WikiPage 格式，钩子是使用场景，「现在」紧凑，记录一行一件、真实日期/出处，四种连线无替代。无日期写「日期未注明」，不把 mtime/文件排序/播种日当事实日。
18. Prompt 槽/字段、CC 文件/段、现有 wiki 页版本成为本次实际读取的真实 Cite；不包装幽灵 Memory、不伪造 f 号，不动 C2 已整理/驳回。提交沿 CatalogItems 的共用来源校验和版本检查；无有效出处的记录丢弃。已有非种子页只产更新提案，不能用重合放行当强盖权限。

21. 复用 CatalogRunRecord：每轮实际请求、文件调用/完整回执、目录、审批结果、页草稿/交审校验、停止/错误及完成判定写同一 `wiki/.runs/`；MemoryWriteLog 每轮带同次链接/anchor，恢复时重新打开原记录，不生成另一份。文件库「整理记录」能打开同次 run，目录/页草稿能看能改；提案明确保存 run link，不沿标题/时间猜。不中途另建进度数据库或种子大屏。
22. .runs/已处理提案原有 30 天清理不能删掉仍在等目录/页生成的任务必要快照；待批会话留到处理完，结束后沿原有留存。日志可过期，未完成任务不能因为日志过期失去获批原料。不重复存多份原料；会话已持久内容供来源/回执展示引用。

**旧数据怎么办**：旧种子从 0，先备份、清单识别、删状态/种子提案/种子生成页，再发新任务；非种子 wiki/提案、原料 CC/Prompt、C2 都不清。清理不是每次日常 C3 动作，也不是自动删 wiki 策略；这次清旧是粟粟已明确授权的一次性 cutover。新种子后维护走日常 C3。
