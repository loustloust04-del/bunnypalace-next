## 0. 先说 4B 为什么半天不回（证据）

Mac 上拿她 Air 的真实聊天记录重放一次请求（`scratchpad/mlx-spike`，同版本 mlx-swift-lm 3.31.3）：

| | prompt | 预填 | 生成 | 峰值内存 |
|---|---|---|---|---|
| 1.7B | **2503 tok** | 2355 tok/s | 80 tok/s | 1.1 GB |
| 4B | **2503 tok** | 854 tok/s | 35 tok/s | 2.3 GB |

- 2503 token 里**工具定义约 2000**（15 个工具，4871 字 JSON），system 约 300，历史约 200。
- 每一轮工具调用都**从头重算整段 prompt**（没复用 KV）。「先读再提案」= 2–3 轮 = 预填 2–3 次。
- 手机 GPU 比这台 Mac 慢几倍（没实测，P0 要测）；4B 首次还要从盘里读 2.2 GB。估计 4B 一问 30–60 s 才出第一个字，看起来就像卡死。
- 追问兜底（v2 刚加的）如果触发，还会再加一轮。

结论：光换模型不解决；要**砍 prompt**（第 5 条不带历史 + 本机只挂用得上的工具）+ **复用固定前缀的 KV**（system + 工具每次都一样）。

## 1. 本机模型进 provider（别的对话也能用）

**做法**：加一种卡类型 `ProviderType.localMLX`，自动建一张固定卡「本机模型」（id `local-mlx`，模型 = 1.7B / 4B，id 形如 `local-mlx/qwen3-4b-4bit`）。`ProviderRouter.sendStreaming / sendNonStreaming` 碰到这类卡，不走 HTTP，转给本机推理服务。这样 Page1 模型选择器、对话级模型、全局兜底都能直接选它，调用点一行不改。

- 推理服务：把现在的 `AssistantLocalBackend` 抽成 `LocalLLMService`（全 app 一个，**串行排队**）。现在的实现是新请求直接 cancel 旧的——主聊天和小芽同时用会互相掐断，必须改成排队。
- 没装好的模型：选择器里灰掉，旁边写「未下载」，点了跳到下载处。
- 旧版 app 读到这张卡 → 已有的 `.unsupported` 兜底，不会炸存档。
- 要补 `case .localMLX` 的地方：`ChatService`（路由）、`APICredentialEditor`、`APISettingsTab`、`UsageLedger`、`CardFlowView` 模型选择器、`FullDocumentMapping`（备份）等约 20 个文件里对 `ProviderType` 的判断（逐个 grep 核，不靠编译器兜——有的是 `==` 判断不是 switch）。
- 主聊天用本机模型时：
  - **工具关掉**（联网 / MCP 那套 schema 更大，小模型扛不住）；
  - 上下文封顶（先定 6k token：预设 + 角色卡 + 记忆先截，历史从新往旧装，装不下就丢）；
  - 图片附件：不支持，发送前提示「本机模型看不了图」。

⧫ D1 后台任务（记忆提取、摘要、梦境整理、内心独白…）要不要允许用本机模型？
  推荐：**不允许**，全局兜底如果是本机模型，后台任务跳过本机、改用下一个云端模型或者这次不跑。理由：后台任务会和聊天抢同一块 GPU，排队时她就得等；而且 1.7B 抽记忆质量很差。
  <⧫>✅ 粟粟 09-26：这次先不允许；未来可以，但得先把 app 保活做了（后台任务在 app 退后台时还要能跑完）。</⧫>

⧫ D2 模型下载 / 删除的入口挪到哪？
  推荐：**挪到「设置 › API」里那张「本机模型」卡的详情页**（和别的卡编辑页一个位置），小芽设置里不再放下载按钮，只放「选模型」（见第 2 条）。
  <⧫>✅ 粟粟 09-26：好</⧫>

## 2. 小芽自己选模型

「设置 › 小芽 › 本地大脑」那块整个换成一行 **「小芽用的模型」**：

- 默认「跟随聊天」（= 现在的行为，用 `selectedChatModel`）；
- 也可以单独选任何一个收藏的模型，包括本机模型；
- 复用 Page1 的 `ModelPickerPopover`（只列收藏，和主聊天口径一致）。
- 存 `xiaoya.model`；原来的 `xiaoya.local.enabled` / `xiaoya.local.model` 迁移一次：开着本地大脑的 → `xiaoya.model = local-mlx/<那个模型>`，然后删旧 key。
- 引擎按选中的模型分：本机卡 → 本机后端（精简 prompt + 不带历史，见第 5 条）；其它 → 云端（照旧）。舞台小票上的小叶子照旧表示「本机在答」。

## 3. 舞台里放设置钮

舞台右上角现在有「账本」钮，旁边加一个齿轮，点开小芽设置（iOS sheet / mac popover），里面就是现在「设置 › 小芽」那一页（舞台主题、权限包、模型）。设置页本身保留，两处是同一个 view。

## 4. md 渲染 + 改以前的输入

- **md**：她的话现在是裸 `Text(msg.text)`，所以 `**粗体**`、列表、代码块都是原样显示。换成主聊天同款 `ChatMarkdownView`（`linkifyTickers: false`，没有划线 / 引用）。左边那条墨线保留。要核一件事：`ChatMarkdownView` 的字色走主题，小芽面板用自己的 `skin.ink`，暗色舞台下可能对不上——做的时候截图比对，不对就给它传字色。
- 流式中还是纯文本（和主聊天一样，生成完才转 md），免得半截 md 乱跳。
- **改以前的输入**：长按自己的话 → 菜单「编辑」「复制」。编辑 = 把原文放回输入框，**从这句开始往后全删**，改完发送就是重新问。

⧫ D3 编辑时后面的提案卡怎么办？
  推荐：还没盖章的直接随消息删掉；盖过章的改动**不回滚**（账本里还在，随时能撤）。删之前如果后面有盖过章的卡，弹一句「后面有 N 张已生效的提案，改动不会撤回，要撤去账本」确认。
  <⧫>✅ 粟粟 09-26：好</⧫>

## 5. 小模型不带历史，大模型带

- 本机模型：只发 system + 工具 + **这一句**。云端：照旧（30 条滑窗 + 提案状态备注）。
- 副作用要讲清楚：她问完「帮我写个角色卡」、小芽反问「叫什么名字？」、她答「随便」——不带历史的话小芽只看到「随便」，接不上。

⧫ D4 本机模型是完全不带，还是带上一轮小芽那句话？
  推荐：**带上一轮**（只带小芽刚才那一句，截 200 字，不带提案备注）。多约 100 token，但「随便」「换一个」「就这个」这种接话能接上。你要是想要完全干净，就一句都不带。
  <⧫>✅ 粟粟 09-26：按推荐，带上一轮小芽那句</⧫>

- 顺手砍 prompt（本机才做）：工具按当前页面挑。比如在世界书页只挂世界书 + 通用读工具，在 Page2 只挂外观那几个。预计 2000 token → 600–900。
- KV 前缀复用：system + 工具这一段每次都一样，算一次存着，之后只算新增的那一句。要先查 mlx-swift-lm 3.31.3 有没有现成的 prompt cache（`ChatSession` / `KVCache` 能不能跨 generate 复用），**先 research 再定**，不行就只做砍工具。

### §5 实测补记（09-26，Mac 上真模型，同一条「帮我写一个新的角色卡 → 小芽反问 → 随便！你自己随意」）

| 发给本机模型的形式 | 1.7B | 4B |
|---|---|---|
| 小芽那句反问 + 「随便！你自己随意」（D4 原方案） | 0/4 | 0/4 |
| 同上 + 规则写「说随便就自己编好直接交」 | 0/5 | 0/5 |
| 「帮我写一个新的角色卡\n随便！你自己随意」 | 5/5 | 0/5 |
| **「帮我写一个新的角色卡。补充：随便！你自己随意」** | 4/6 | **6/6** |
| 同上 + 本机提案工具描述补「细节自己编，不要反问」 | **6/6** | **6/6** |
| 闲聊「今天好累啊」（全挂工具） | 照常聊 | 照常聊 |

所以 D4 换了实现形式、目的不变：**小芽上一句是反问（没交卡、问号结尾）时，把她再上一句并进这一句**，写成「上一句。补充：这一句」；否则只发这一句。小芽的原话不带。
工具按关键词挑之后，这条请求的 prompt 从 2503 token 降到 872。

## 6. 顺序 & 验收

P0 → P1 → P2 → P3，每步 build + 单测 + 装 Air 给你验。

- **P0 测速（先做，半小时）**：本机推理打点（加载 / 预填 token 数与耗时 / 首字 / 生成速度）写进 BreadcrumbLog，装 Air 用 1.7B、4B 各问一句，拿到手机真实数字。数字决定第 5 条砍到什么程度。
- **P1 小的先上**：3 舞台齿轮 + 4 md / 编辑 + 5 不带历史 + 本机挑工具。
- **P2 本机进 provider**：1 + 2（`LocalLLMService` 排队、卡、路由、选择器、迁移、下载入口挪位）。
- **P3 KV 前缀复用**（看 research 结果，可能不做）。

验收：
- Air 上 4B 从发送到出第一个字 ≤ 8 s（P0 拿到基线后再校准这个数）；
- 主聊天选「本机模型 · 4B」能聊；同时小芽在答时主聊天排队、不掐断；
- 小芽气泡里 md 正常渲染（粗体 / 列表 / 代码），长按自己的话能编辑重发；
- 舞台齿轮能打开设置、改完立刻生效；
- 旧版本地大脑开关迁移正确。
