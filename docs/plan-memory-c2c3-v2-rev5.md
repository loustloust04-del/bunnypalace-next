## 第一性原理（粟粟 10-22：「规矩是死的人是活的，所有你这种顾头不顾尾巴的瞎加一些规则都给我第一性原理思考」）

1. **C3 的目的**：把碎片池和时间轴整理成 AI 用得上的 wiki，页写连成线的事实。
2. **wiki 是用户的**：用户随时可以新建、改名、删页、改触发词。模板只是起点，不是结构。
3. **归哪页、开不开新页**，是对着**此刻实际存在的 wiki** 做的语义判断。凡是写死的东西都会在用户改 wiki 的那一刻坏掉：固定的路由表、固定的子页清单、为 C3 往 C2 加的字段。用户新建一份 md，不应该还要去改代码或者改 C2。
4. **代码只做它确定能做对的事**：编号、出处、格式、计数，以及「碎片里直接出现了某个现有页的标题或触发词」这种字面比对。语义判断交给模型。
5. **上游不可信**：C2 的 subject、tags 只当线索，不当标准答案。C2 的质量单独量，不靠改 C2 的结构来补。

下文每一条都要能追到这五条；追不到的规则不加。

## §0 对照 Karpathy 基础 LLM wiki

Karpathy 那套的要点，据二手整理，原 gist 未逐字核对：
- 原料不可改，LLM 写的页单独放；
- 有总目录 `index.md` 和只追加的 `log.md`；
- ingest：来一份原料，更新相关的多页和目录，记日志；
- query：先读目录，答案带引用，好答案可以存回 wiki；
- lint：查矛盾、被推翻的说法、孤页、缺的交叉引用。

### 两种分拣，都对着「此刻实际存在的 wiki 索引」

| | 代码基线（默认） | 模型（可选） |
|---|---|---|
| 归已有页 | 碎片的 subject / tags / content 里**字面出现**某个现有页的标题或触发词（复用 `WikiInjection.match`）。只中一页就归它；中多页记「拿不准」，不归 | 模型读碎片和实时索引（路径、标题、别名、钩子），归到最贴的页 |
| 开新页 | 没对上任何页的碎片按规范化 subject 聚，同组 ≥3 条且 subject 没字面对上任何现有页 → 以 subject 提开页；subject 是 `{u}` 本人 → 提「整理 {u} 本人」方向，拆不拆页交写手；无 subject 的旧碎片按旧规则；tags 只用于对已有页，不用于开新页（10-22 改：tag 词频会把「习惯」「计划」这类泛词提成新页，粟粟「很诡异」；C2 subject 修好后 subject 本身就是「谁 / 什么」） | 模型提开新页，代码核同一新页名下 ≥3 条碎片 |
| single | 不判，交写手 | 模型可判；会变的状态不能 single |
| 用户新建 / 改的页 | 下一轮就按它的标题、触发词参与比对，不改代码 | 同上，索引是现读的 |

- **模型分拣的提示词**：用新稿第 2 部分，删掉固定路由表和固定子页清单，改成「对照索引里现有的页」，其余照用，示例换虚构 `{u}` / `{c}`。
  - 输出照新稿 JSON。代码校验：能解析、每条都判了、page 在索引里、new 的类合法。不过给一次重写，再不过本轮失败、记日志、不提方向。
  - C3 页加「分拣：代码 / 模型」，默认代码；选模型时用 C3 所选模型，计入写入预算。
- **两种交出同一种方向提案**，每条写明归页理由，比如「碎片含该页触发词 X」「tag 词 Y 出现在 3 条碎片」「模型：……」。后面的搜索、写作、两批审批不变。
