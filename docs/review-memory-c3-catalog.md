## 〇、这一段做了什么

- **存储**：`memory/wiki/` 一个点一页 md，`.history` 存整页旧版，`.proposals` 放提案和模型原始输出草稿。索引由代码生成，根下分「工程 / 楼层」两支，一层超过 30 行打「待分组」。
- **碎片标记**：`Memory` 加三个可选字段 `organizedAt` / `organizedPage` / `organizeRejectedAt`。轻量迁移，备份镜像两向同步。⚠️ 表结构变化，装 Air 时 Warden 指纹闸会拦，按「加可选字段、轻量迁移」报。
- **A 线搜**：`ALineSearch` 按 A4 → A3 → A2 逐层逐字搜，有上限，老格式带「旧」标。另有 readWindow / readSegment 两个读取口。
- **整理**：
  - 自动：两步。先分拣（归到已有页 / 新主题 / 单条就够），再逐主题写；超 30 行的层另提「分组调整」。
  - 手动：真 agent。只读工具，最多 10 轮、工具结果累计 40000 字封顶，每一轮都过写入预算和全局闸。
  - 调度：每天过 05:00 第一次在前台时跑；同一楼层互斥，能停。
- **C2**：默认模板加可选 `valid_until`。衰减里「过期压到 0.05」那几行删了。
- **设置**：C3 写手转正，有二级页（每天自动 / 自动一次最多几个主题 / 手动最多几轮 / 不触发的词）。
- **审计台第四格「整理提案」**：现在整理、整理一个主题、停；提案卡和详情，逐条批 / 改 / 驳回，整批批 / 整批驳回；碎片卡上加一行小字。
- **看 wiki**：
  - 文件库里显示「C 档案」，页能编辑、有历史；
  - 记忆格加「wiki · N 页」，一层层点进去看；
  - 小克的 fs 工具看不到 wiki 内部文件。
- **验证**：mac + iOS build-for-testing SUCCEEDED。定向 36 个套件 426 个测试全过；PromptRealPathGolden / InspectorRealPath 原样通过，没有 RECORD。

## 一、边界情况（没处理 / 处理得粗的）

1. **本机模型做 C3**：本机路线有 6000 字上限，分拣和写主题时喂进去的料超长会被截断，整理效果会很差。设置里没拦，只在复盘这里记一笔。
2. **一次分拣最多 150 条**：没送过的先送，其余按上次送的时间轮转；不够 3 条门槛的新主题进「暂存主题」，以后来的碎片能补进去。第一次池子里积压很多时，要跑好几天才能分完；手动「现在整理」也是一次 150 条。
3. **「今天跑过了」先记下再跑**：当天被预算拦下或者出错，不会再重试，第二天才补。换楼层时只跑当前楼层，别的楼层等那个楼层自己打开的那天。
4. **分到某个主题、但写手没用上的碎片**不打标，按「上次送分拣时间」轮转再送（astra 6/7 返修后）。写手判「已被现有页覆盖」（covered）、但这一页这次一条条目都没写时，直接标「已整理进」这页，不经她批（和「单条就够」一样只打标、不改 wiki，否则会反复送去花钱）。
5. **「页已变」只在批的那一刻判**：详情页不预先比对版本，要点了「批」才会发现并置灰。
6. **批了一半失败**：已写的页、碎片标记不回滚，提案照样存盘；失败只给一句红字，不发记忆变更通知，wiki 列表要等下一次变动才刷新。
7. **「连到」里认不出的行**：页被提案重写时，会从原位置挪到已解析链接的后面（内容不丢）。
8. **`.group.md`（分组钩子）没有手改入口**：文件库里隐藏，只能通过「分组调整」提案改。
9. **「它搜了什么」**：返修后日志记了搜索词和路径。被预算拦下的那一行前缀不同，不出现在审计台，只在记忆日志里。
10. **A 线出处跳不到具体那一段或那条消息**：现在是弹窗口总结（A3 + A2 各段），再点「去这个窗口」，段号和消息范围只当文字显示。碎片出处能跳到那条消息。
11. **记忆树弹层（MemoryTreeBrowserSheet）里的 wiki 页仍然只读**；能编辑的只有文件库和记忆格。
12. **分组调整挪空的旧文件夹不删**，里面留着 INDEX.md / .group.md。
13. **被拦或点停时**，agent 如果还一条都没交，这个主题就不出提案（plan 4.1b 原写「交一份没整理完的提案」）。被拦时只把工具调用摘要存进草稿、记一行日志。只有到了轮数或字数上限、被逼着交上来的，才标「没整理完」。
14. **「不触发的词」设置页的脚注**写的是「聊天里出现这些词，不会带出 wiki 页」，但触发词注入是第 ② 段的事，这一段只存不用。
15. **C3 不归复杂度滑条管**：滑条的四档是 C3 之前定的，拖滑条不会开关 C3，「开 N 项」也不数它。要不要把 C3 并进「重」档，等粟粟定。

## 〇、做了什么

- **【开窗口】C 勾着时带三样东西：**
  - 稳定层：B4 后面放「[C 档案 · 索引]」，就是根 INDEX 的条目行，保留 `[[路径]]`，小克可以顺着 fs_read 往下翻；

收口：⑤ 之后不再开新一轮审查。最终是 40 个套件、625 个测试全过，mac 和 iOS 都编过，金样原样。

**技术债 / 遗留：**
1. **CC 的「未发送」状态不持久化**：`CCSendTracking` 只存在内存里（1 小时 TTL，最多 200 条），app 重启后徽章消失。要持久化得加 model 字段，改了 schema 就得先做 Air 完整备份，留到下周弄记忆时一起定。
2. **发送排队这一块越改越复杂**（`ConversationViewModel` 里有 `pendingSends`、`queuedCCSends`、入队序号、门控），这一轮是在现有结构上打补丁。以后再动发送管线，应该先把它收成一个统一的发送调度器。
3. **「交了 0 条」的根因没有实证**：要等装上带取证的版本后，粟粟再跑一次，看 drafts 里落下的东西。
4. **iOS 只编译没跑测试**：发送和草稿相关的测试都是在 mac 测试宿主上跑的，iOS 输入栏的差分持久化要在设备上看一眼。

## 四、要在设备上看的

1. 常驻页「C 档案」一行：根索引行数对不对；发一句带页标题或触发词的话，「本轮命中」显示哪页、哪个词。
2. 检查器 / 注入预览里：根索引在 B4 后面，命中页在动态段，命中碎片只有「留下」的，钉住的照带。
3. 发一条带「不触发的词」或用户名的消息，不应该带出同名页。
4. 关掉【开窗口】C：三样都不带。
5. **整理一个主题**（例如「电影」）：应该能交出提案；交空的话，日志会写 drafts 文件名或空交的理由。
6. 一个对话正在回复时，在另一个对话里连发几条，或者切走、切回：排队的消息要么依序发出，要么回到输入框，不能凭空消失（iPhone 和 mac 都要看）。
7. 重新生成、编辑重发之后马上点停止：停回原来那条回复，后面的消息还在。
