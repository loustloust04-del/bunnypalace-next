## 三、文件库数据模型

**纯 POSIX 目录树，零类型/分组抽象。**

- 根 `~/Documents/记忆宫殿/floors/{emoji+楼层名}-{profileId前8}/`（`FileLibraryStore.swift:394-399`）
  - `filesystem/` 可读写，跟随 iCloud（`:28-96`）
  - `memory/` 只读记忆树，**永远本地**（`:301-307`）
  - `.memorypalace/manifest.json` 楼层身份锚（`:9-15,444-457`）

**目录语义 = 散落在各服务里的硬编码约定**（不是 schema）：

| 目录 | 语义 | 定义处 |
|---|---|---|
| `books/{safeName}/` | 书 | `BookStore.swift:7-19` |
| `topics/`、`topics/archived/` | 话题盒 | `TopicBoxStore.swift:37-39` |
| `vocab/<word>.md`、`vocab/img/` | 词条笔记 | `VocabNoteStore.swift:15,42` |
| `trading/<SYM>.md`、`trading/<SYM>/`、`trading/journal.md` | 交易 | `TradingNoteStore.swift:9,34`、`TradingStore.swift:30` |
| `attachments/{conv前8}-{标题}/` | 对话附件 | `FileLibraryStore.swift:752` |
| `reading-log.json`、`reading-events.jsonl` | 阅读信号 | `ReadingSignals.swift:16-22` |
| `memory/*` | 记忆树 | 各 Store |

UI 树视图运行时按 `/` 切路径段现搭（`FileLibraryPanelView.swift:638-653`），**不落盘、不带元数据**。

**AI 工具**（`Services/FileLibraryTools.swift:14-107`，注册 `ToolRegistry.swift:18-24`，闸 `fileLibraryEnabled`）：`fs_list`/`fs_read`/`fs_search`/`fs_write`/`fs_append`/`fs_edit`/`fs_rename`/`fs_delete` + `update_profile_card`。
- `fs_list`/`fs_search` **合并** filesystem/ + memory/（`:64,70`）
- `memory/` 前缀 read 放行、写操作**一律拒**（`:46-58`）
- 写操作回灌紧凑 diff（`:115-199`）
- 白名单：文本 `md/markdown/html/htm/txt/json/css/js`；二进制 `png/jpg/…/mp4/bin`（`FileLibraryStore.swift:634-673`）
- 拒绝绝对路径与 `../` 越狱（`:163-173`）

**frontmatter**：有但**三套解析器各写各的**——`FrontmatterCodec`（`Services/FrontmatterCodec.swift`，记忆树五种文件用）/ 话题卡自解析（`TopicBoxStore.swift:104-125`）/ 研报自解析（`TradingStore.parseFrontmatter`）。**普通文件库文件零元数据**（只有 mtime/size）。

## 四、事件 / 时间线节点

**没有独立事件对象。** 最接近的四个都不可寻址：

1. **日记 `daily/{date}.md`** — 时间线**容器**不是节点：一天一篇散文，事件以自然语言存在，无字段无 id 不可单独引用
2. **`✦moment` 行** — 唯一带"事件"语气的：AI 在思考链写 `心声:`/`✦时刻:` 开头的行，**结算日记时才正则捡**（`TimelineConsolidator.swift:177-209`），不落库不可寻址，捡完融进散文。设置页「Moment（事件感知）」是 `unimplementedRow` 死行（`MemoryPageContent.swift:138`）
3. **`reading-events.jsonl`** — 真结构化事件流 `{ts,type,book,chapter,word}`（`ReadingSignals.swift:38-44`），**只上行给 hub，app 内零消费者**，不注入
4. **`trading/journal.md` + TradeEntry** — 唯一有生命周期的事件对象（开仓→平仓→复盘挂同一条，`Models/TradeEntry.swift:7-34`），但语义封闭在交易域

`Memory` 有 `createdAt`/`sourceQuote`/`sourceNodeId`（`Models/Memory.swift:35-37`）能定位"哪条消息说的"，但它是**事实**不是**事件**——无 duration、无参与者、不组成序列。

## 五、重复与冲突

**D1 · 同一事实四处存在，可同时注入三次**
「用户喜欢暖奶白」会：①Memory 进 order 40 ②做梦凝进 profile.md 进 order 39 ③窗外对话里说过则进 summaries 的 order 55 ④当天说的进 daily 的 order 38。半个防线：做梦后毕业消费碎片（`DreamConsolidator.graduateConsumedMemories:181-196`）——**只在 `mem_supersede_soft=true` 生效，钉住豁免（`:174-176`），且不管摘要和日记**。摘要/日记/画像三方**零去重**。

**D2 · 提取器只看得见画像，看不见摘要和日记**
`buildPrompt` 喂 `{{PROFILE}}` + `{{MEMORIES}}` + `{{SYSTEM_PROMPT}}`（`MemoryService.swift:976-1000`），规则 11「画像已涵盖的别 add」。摘要/日记不在视野 → 已被摘要吸收的事实照样重新 add。

**D3 · 三级二次加工，日记显式承认会串日期**
日记吃摘要（`TimelineConsolidator.swift:119-121`），prompt 专门写「可能包含早于当天的内容——只用来补充语境，别把旧事写成今天」（`:218`）。原文 → 摘要 → 日记 三层压缩，各自都在注入。

**D4 · 画像防写清单与碎片提取规则口径不一致**
画像明确禁写性偏好/亲密细节/AI 与用户的称呼与私密玩笑/角色扮演事实（`DreamConsolidator.swift:87-92`）；**碎片提取器无对应禁令**（只有规则 12「人设是角色扮演时输出空 actions」，`MemoryService.swift:960`）。这类内容会以碎片形式注入 order 40，只是不进画像。

**D5 · 宏与约定段双份注入同一批数据**
`composedHealthSummary` 走宏，同时 `healthLogHint` 把「当前的药：X（8:00/21:00）」再写一遍进文件库段（`CV:2586-2591`）。交易同理（`CV:2550`）。两路各有闸，可同时开。

**D6 · 话题盒账本与卡片分居两个存储**
卡片在 `filesystem/topics/*.md`（跟 iCloud），账本在 `App Support/MemoryPalace/topicBox/{profileId}.json`（本地，`TopicBoxStore.swift:66-74`）。开 iCloud 后卡片跨设备、账本不同步 → 每台设备各掉各的。`reconcile` 只能对账「文件没了就剔除」（`:322-326`）。

**D7 · `journal.md` 与 `TradeEntry` 是同一事实两份副本**
每次落卡同步 append 人话版进 `trading/journal.md`（`TradeLogIntentWriter.swift:98,116,133`，注释「防丢镜像，开单理由丢不起」）。SwiftData 那份可编辑可删，md 那份 append-only 且 AI 能 fs_read —— **两份会漂移，无对账机制**。

## 六、意外发现（12 条）

**F1 · `MemoryNote` 是彻底僵尸。** 在 SwiftData schema（`MemoryPalaceApp.swift:154`）、全局备份 schema（`FullDocuments.swift:173`）、SchemaCoverageCheck 必填清单（`:125`）里，但零生成零消费零 UI，搜索显式跳过（`SearchService.swift:667`）。全部作用是让备份/恢复/schema 校验三处继续维护一个死字段集。

**F2 · 心声根本不进 prompt。** 5 个记忆文件物种里唯一**无注入路径**的——AI 写 400 字独白，下轮完全不记得，除非自己 `fs_read`（而注入段的记忆树提示没点名心声，`CV:2498`）。唯一传播路径是当天结算日记时收割成一行（`TimelineConsolidator.swift:150-155`），而日记默认关（`mem_content_timeline`=false）。**默认配置下写完即入土。**

**F3 · 4 个真死开关 + 2 个 unimplementedRow。** `mem_content_facts`（"原子事实"，可点、默认开、**无任何代码读它**）、`mem_inject_tag`、`mem_content_filehistory`、`mem_infra_gateway`。后三个至少被标了「· 未实现」并 disable，**「原子事实」传的是 `true`（`MemoryPageContent.swift:132`）——看起来是活的**。实际关掉它提取照跑（提取只受 `mem_master` && `conversation.memoryEnabled` 管，`CV:2684`）。

**F4 · 关掉「文件库」会连坐掐掉四个无关子系统。** `fileLibraryEnabled=false` → `hint=""`（`CV:2408`）→ 话题盒约定、正在读的书、健康约定、交易约定、记忆树提示**全部消失**（它们都拼在 `fileLibrarySystemHint()` 里，`CV:2494-2498`）。UI 无任何提示。

**F5 · 文件库面板看不见记忆树。** 只调 `list` 不调 `memoryList`（`:660,678`）。AI 能 `fs_list` 看到全部，用户在 app 内**没有浏览器**——只有三个特化入口（画像在设置页、日记在日历、心声在资料卡），**摘要完全无 UI**。

**F6 · 记忆树对 AI 只读是硬拒，但文件库里的「准记忆」全可写。** `memory/` 写被拦死（`FileLibraryTools.swift:54-56`），但 `books/{id}/notes.json`、`trading/journal.md`、`topics/`、`reading-log.json` 都在 `filesystem/` 下 —— AI `fs_write` 技术上能覆盖。对 notes.json 的保护只是注入段一句人话「只读——不要直接改它」（`CV:2520`），**零机械强制**（`.json` 在文本白名单里，`FileLibraryStore.swift:634`）。

**F7 · `VocabProgress` 是全库唯一无 profileId 的 @Model**（`Models/Vocab/VocabProgress.swift:17-21`，刻意：「词汇量是粟粟本身的属性」）。但**笔记正文 `vocab/<word>.md` 分楼层**（`VocabNoteStore.swift:15`）。同一个词 A 楼层写的笔记 B 楼层看不到，学习状态却共享。

**F8 · 全量注入已取代检索。** 「刀4」把注入资格从 `listHot`（≥0.3）改成 `listActive`（没 superseded 就全进，`MemoryService.swift:137-146`），预算 2000→10000，**并一次性清掉用户设过的 keyword/vector 开关**（`migrateFullPresenceIfNeeded:269-279`）。默认 `activeRetrievers()` 返回 `[PersistentRetriever(explicitOnly:true), FullFallbackRetriever]`（`:556-558`）—— **BM25/向量/RRF/graph 在主注入路径上默认全不跑**，只活在 `recall` 工具里（`RecallTool.swift:236-241` 显式绕过灰开关双路直调）。

**F9 · 注入排序被缓存约束钉死，不是语义选择。** 两个 Retriever 都按 `createdAt` 排（`:384,492`），注释写明「按权重排的话 reinforce/衰减每轮微调分数，行序随时翻面 → system 前缀变 → 缓存无声全废（实测踩过）」。**任何「按重要性/相关性重排记忆」的重构会直接撞上这条已验证约束。**

**F10 · 日记的日期归属是已知近似。** `pendingMaterials` 按 `Conversation.updateTime` 归日（`TimelineConsolidator.swift:97` 注释「连续多日聊同一对话时只算最后一天」）——userLines 按 `MessageNode.createTime` 精确取，但**候选对话集本身**用对话级 updateTime，跨日长对话前几天整段漏掉。

**F11 · ccBridge 路径下记忆注入全部作废。** `prepareRouterPayload` 对 ccBridge 只发 raw user 文字（`CV:1895-1897`），组装结果被丢弃；召回卡片也不写（`CV:2315-2318`，注释「不写卡片数据免得撒谎」）。**走 CC 桥聊天时画像/日记/记忆/摘要一条都进不去，但提取/做梦/日记/摘要照常跑**（在 `onComplete` 里不看 provider 类型，`CV:2684-2696`）—— **单向写入、零读取**。

**F12 · `FileLibraryStore.search` 全文件全行扫描无索引。** `search`/`memorySearch` 逐文件读全文再逐行 `range(of:)`（`:345-370`）。`fs_search` 一次调用把 filesystem/ + memory/ 下所有文本文件读进内存。
