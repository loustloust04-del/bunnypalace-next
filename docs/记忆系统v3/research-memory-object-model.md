## 0. 我理解的需求（先纠错这一节，错了后面全白写）

现在这四样东西是搅在一起的，你要把它们拆开：

| 你说的 | 我理解的意思 | 现状是怎样 |
|---|---|---|
| **档案** | 结构化的、当前有效的**对象**：人、领域、话题、关系。有字段、可检视、可引用、可被 AI 和人共同维护 | 不存在。最接近的是文件库里一堆按目录名约定俗成的 md（`trading/` `vocab/` `topics/`），零 schema 零类型 |
| **画像** | **是档案的一种**（"关于粟粟这个对象"的那一份），不该是做梦的产物 | 现在恰恰是做梦生成的一坨 ≤1500 字散文，覆盖式重写 |
| **做梦** | 是**另一个动作**，不是"生成画像" | 现在被占用成了"把碎片凝成画像" |
| **事件节点** | 时间轴上发生过的事，也是一种档案对象 | **不存在独立事件对象**（详见 §3.C） |

**「AI 的 Unity」我理解为**：档案不是文档，是**对象**——有类型（人/领域/话题/事件）、有字段（不同类型不同字段）、有引用（对象之间连线）、有检视器（打开能看到它的所有面）、能被脚本读写。你管游戏对象怎么管，就管档案怎么管。

**「活的档案」我理解为**：不是写完就躺着的归档，而是①AI 每轮会自己更新 ②更新有纪律（阈值、去重、压缩、冲突处理）③人随时能改 ④改了立刻影响下一轮对话。

⧫ **这一节哪里错了，直接在这划掉重写。**

### 1.2 死的 / 半死的（这些是重构时该直接砍掉的包袱）

- **`MemoryNote`**：零生成零消费零 UI 的僵尸 @Model，但备份/schema 校验三处还得养着它
- **心声 `heartvoice/`**：**唯一没有任何注入路径的记忆物种**。AI 写完 400 字独白，下轮完全不记得写过。唯一出路是当天结算日记时被收割成一行——而日记默认关。**默认配置下，心声写完即入土**
- **`✦moment` 事件行**：AI 在思考链里写的"✦时刻:"，只在结算日记时被正则捡走融进散文，不落库不可寻址。设置页那行「Moment（事件感知）」是死行
- **4 个死开关**：`mem_content_facts`（"原子事实"，看起来是核心开关，**实际没有任何代码读它**）、`mem_inject_tag`、`mem_content_filehistory`、`mem_infra_gateway`
- **`reading-events.jsonl`**：真正结构化的事件流（`{ts,type,book,chapter,word}`），但只上行给 hub，**app 内零消费者**

### 1.3 关键：检索管线默认全部不跑

「刀4·全量在场」把注入资格从 `listHot`（衰减≥0.3）改成 `listActive`（没失效就全进），预算提到 10000，并**一次性清掉了用户设过的 keyword/vector 开关**。默认配置下注入路径只有 `PersistentRetriever(explicitOnly)` + `FullFallbackRetriever`——**BM25、向量、RRF、图谱这整套检索在主注入路径上全不跑**，只活在 `recall` 工具里。

> 这条直接关系到你说的「相关≠想起」：**现在根本没有"相关性"这一步**，是全量倒进去。要谈"想起"的机制，得先决定还要不要回到检索。

## 2. 三个参照物拆解

### 2.1 Claude 官方 Memory files（你的截图）

结构：**分组 → 文件 → bullet 列表**。`You/Profile`、`Topics/{Ai Persona, Health, Interests, Reasoning System, Self Description}`、`Areas/{Babel, Ibkr Investing, Memory Palace, Self Hosted Infra}`、`People/{Jhen, Lucie, Qiaoqiao, Yuriko}`。每份带一行 description（"How 粟粟 relates to Claude/AI — persona framing, prompt-engineering interests, model-welfare views"），编辑入口是自然语言（"Tell Claude what to change or remove"）。

- **强**：分组即类型（You/Topics/Areas/People 就是四个对象类）；人可读；增删类别自由；自然语言编辑
- **弱**：bullet 无结构 → 没法查询/比较/聚合；没有字段，"关系好感度"这种东西无处安放

### 2.2 酒馆表格插件 `st-memory-enhancement` v2.2.8（亲读源码，详见 [对标-酒馆表格插件.md](对标-酒馆表格插件.md)）

六张 schema 冻结的表（`data/pluginSetting.js:353-373`）：

| 表 | 列 | 语义 |
|---|---|---|
| 时空 | 日期/时间/地点/此地角色 | **只保持一行** = 当前状态 |
| 角色特征 | 角色名/身体特征/性格/职业/爱好/喜欢的事物/住所/其他 | 不易变的属性 |
| 角色与{{user}}社交 | 角色名/关系/态度/**好感（-100~100）** | 关系是**带数值的字段** |
| 任务约定 | 角色/任务/地点/持续时间 | 有到期 |
| 重要事件历史 | 角色/事件简述/日期/地点/情绪 | **事件节点** |
| 重要物品 | 拥有人/物品描述/物品名/重要原因 | — |

每表元数据：`enable`/`Required`/`asStatus`/`toChat`/`note`（给 AI 的一句思考提示，如"思考本轮是否该赴约"）。

**真正值钱的不是表，是纪律**：
- **schema 冻结**：表的增改删 PROHIBITED，`freezeSchema: true`，AI 只许填值不许改结构
- **入表阈值**：`plotCriticality≥3`、`emotionalShift≥2`、物品 `symbolicImportance≥5`；连续 3 个相似事件触发急停
- **分层压缩**：10 条原始事件 → 1 条一级摘要（模板化，≤200 字，**生成后锁定**）；3 条一级摘要 → 高级综合
- **保护标记**：`[TIER1]` `[MILESTONE]` 免疫清理
- **冲突不自动猜**：时间悖论 → 冻结 + `⚠️REQUIRES_ADMIN` 等人裁
- **AI 每轮全量重写整张表**（输出完整 JSON），不是增量 patch

### 2.3 Unity

`GameObject` = 空壳 + 一组 `Component`；`Prefab` = 模板；`Inspector` = 检视器；引用 = 拖拽赋值；`Scene` = 当前加载了哪些对象。

映射到档案：**对象 = 档案条目**（一个人 / 一个领域 / 一件事）；**Component = 面**（同一个对象可以有"基本事实"面 + "我们之间"面 + "时间线"面）；**Prefab = 类型模板**（"人"这个类型自带哪些面）；**Inspector = 档案详情页**；**Scene = 本轮注入了哪些对象**。

### 2.4 三者合起来看

| | Claude 官方 | 酒馆表格 | Unity |
|---|---|---|---|
| 单元 | 文件 | 行 | GameObject |
| 类型系统 | 分组（4 类） | 表（6 张，冻结） | Prefab（可扩展） |
| 结构 | 无（bullet） | 强（列） | 强（Component） |
| 谁维护 | AI + 自然语言 | AI 每轮全量重写 | 人 + 脚本 |
| 纪律 | 无 | **强（阈值/压缩/保护/冲突）** | 编译器 |

**你要的东西 = Claude 的类型分组 + 酒馆的字段与纪律 + Unity 的对象/引用/检视。**

## 4. 六条会卡住架构的硬约束（重构前必须知道）

1. **注入排序被缓存钉死**：`PersistentRetriever`/`FullFallbackRetriever` 都按 `createdAt` 排，代码注释写明"按权重排的话 reinforce/衰减每轮微调分数 → 行序随时翻面 → system 前缀变 → 缓存无声全废（实测踩过）"。**任何"按重要性/相关性重排"的设计会直接撞上这条已验证约束**
2. **ccBridge 路径记忆全作废**：走 CC 桥聊天时组装结果被整个丢弃（只发 raw user 文字），但提取/做梦/日记/摘要**照常跑**——**单向写入、零读取**。你用小克聊天时，这套系统在往里写，但小克读不到
3. **同一事实四处重复**：碎片（40）+ 画像（39）+ 摘要（55）+ 日记（38）各存一份，可同时注入三次。做梦的"毕业"只管碎片，摘要/日记/画像三方之间**零去重**
4. **提取器看不见摘要和日记**：只喂了画像 + 现有碎片，所以已被摘要吸收的事实照样重新 add
5. **文件库无类型系统**：纯 POSIX 目录树，目录名是散落在各服务里的硬编码约定，UI 树视图运行时现搭、不落盘
6. **`fs_search` 是全文件全行扫描无索引**：一次调用把 filesystem/ + memory/ 所有文本文件读进内存

## 5. 分类学草案（这是最需要你拍的部分）

我的提议是**按"回答什么问题"分**，不是按"谁生成"分：

| 层 | 回答的问题 | 形状 | 谁维护 | 注入策略 |
|---|---|---|---|---|
| **档案 Archive** | "X 是什么 / 现在怎样" | **对象**：类型 + 字段 + 引用。人/领域/话题/物 | AI 按纪律更新 + 人随时改 | 按"本轮关联到哪些对象"选择性注入 |
| **事件 Events** | "发生过什么" | **时序节点**：时间 + 参与对象 + 摘述 + 情绪/重要度 | AI 按阈值记 | 近期全给 + 远期给摘要 |
| **画像 Profile** | "这个人是谁" | **档案的一个特例**（"粟粟"这个对象的档案），不是独立物种 | 同档案 | 常驻 |
| **做梦 Dream** | "这些东西之间有什么我没注意到的联系" | **动作**，不是文档：在对象与事件之间**建立新连接**、发现模式、提出疑问 | 定期后台跑 | 产出是**边**和**提问**，不是一坨散文 |

**关键判断：做梦不该产出文档，做梦该产出"连接"。**

你说过「相关≠想起」——人想起一件事，靠的是线索之间的**连接**（时间/人物/情绪/场合），不是相似度 top-k。现在的系统两样都没有：注入是全量倒，做梦是写散文。如果做梦改成"在档案对象之间连线、标注为什么连"，那"想起"就有了**可走的路径**，而不是靠向量距离猜。

⧫ **这个对做梦的重新定义，是我从你那句「相关≠想起」推出来的，可能推过头了。你说对不对。**
