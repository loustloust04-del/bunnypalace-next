## 1. 边界情况

- **旧历史**：v1 的待盖章卡没有改前值，解出来一律变「旧版提案，已失效」，只读，不能盖；v1 已经被处理掉的卡当时就从历史里删了，不存在。整份解不开时原文件改名 `history.corrupt-<时间>.json` 留底，不会被空数组覆盖。
- **盖章闸门**：同一张卡双击只落一次（状态先核 + 账本按提案 id 幂等）；丢弃 / 失败 / 撤销 / 旧卡都不能再盖；关掉「创作」之后，历史里还挂着的待盖章卡也会被拒（卡变红字失败）。
- **改前值不一致**：提案之后你手动改过目标 → 盖章失败，卡片说「在这之后被改过，让小芽重新看一眼」。空字符串是合法改前值。
- **同层换了预设**：插槽 / 采样提案锚在 presetId 上，同一层换了预设也判失效（astra B3），不会改到另一份。
- **撤销冲突**：盖章后又改过 → 先弹「这之后又被改过，撤销会覆盖」再确认；「新建预设」的撤销只在楼层还在用那份新预设时才做（否则直接说做不了，不强删）；删掉的条目按原位置插回。
- **写账失败**：改动已生效但账本没写进去 → 卡片如实写「已经生效，但没记进账本（这笔没法撤销）」，不显示撤销。
- **切楼层**：生成中切楼层自动取消（不闪 Shock），旧一轮晚到的 token / 工具回调按 runId 丢掉；工具执行前再核一次楼层没变。
- **世界书存盘失败**：只把这本书的条目放回原样再报错，不做全 context rollback。

## 2. 与下一模块交互的风险

- **P3 外观包要进同一套机制**：新增 `AssistantChange` 的 case（Page2 外观 patch / 单图标 / 窗口皮肤）+ `AssistantWorkspace` 的对应读写 + `XiaoyaPack.appearance`。`XiaoyaPack.of(kind:)` 现在写死返回 `.creation`，加外观时要改成按 kind 分。
- **粟粟 09-26 新方向「剪纸舞台」会动 P1 的皮肤**：`XiaoyaSkin` / 舞台 / 九张脸的呈现都可能重做（她要「顶部舞台和底部不同色、小芽也变剪纸、不怕亮暗主题」）。P3 的「窗口皮肤」工具要等剪纸方案定了再定字段，否则白做。
- **AssistantEngine 构造参数**：现在可注入 store / ledger / packDefaults（为了测试）。P4 的 backend 抽层也走构造注入，保持一致。

## 3. 技术债

- **聊天记录仍是全量留档**（粟粟 09-11 的决定），只改了写盘方式（合并 + 后台）。卡片现在带完整改前 / 改后值，长期会比 v1 大；目前没有体积上限。
- **账本和聊天记录两个文件没有事务**：业务成功 → 账本写失败的情况已如实标注；反过来「账本写了、历史没来得及存就崩」时，下次打开卡片会是 pending，但盖章会走账本幂等直接变已批准，不会落第二次（测试覆盖了幂等路径，没覆盖崩溃时序本身）。
- **提案卡对照只截前 600 字**，超长人设看不全（没有展开）。
- **`XiaoyaSettingsTab` 的开关**用 `@AppStorage` 默认 true，跟 `XiaoyaPackPolicy` 缺键默认一致，但两处各写了一次默认值（都取自 `pack.defaultEnabled`）。
- 离屏快照脚本仍未入库（理由同 P1）。
