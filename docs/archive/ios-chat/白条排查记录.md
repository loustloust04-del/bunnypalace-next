# 记忆宫殿 — 顶部白条排查记录

> 2026-02-26

## 问题描述

窗口顶部 detail 区域（右侧）始终有一条约 52px 高的白色横条。对比 Claude 桌面 app：Claude 的标题栏默认完全透明，只有鼠标移上去才出现红黄绿按钮；记忆宫殿的白条始终可见。
现在的白框只在全屏有。

用户在 Xcode 3D View Debugger 中发现白条由 **4 层 view 堆叠**而成：
1. splitviewchildcontroller（最前面）
2. navigation splitviewchild controller
3. appkit window hosting controller
4. appkit window controller（最后面）

## 已有的窗口配置（baseline）

```swift
// MemoryPalaceApp.swift
window.titlebarAppearsTransparent = true
window.titleVisibility = .hidden
window.backgroundColor = NSColor(...) // #FFFBF6
window.styleMask.insert(.fullSizeContentView)

// Scene
.windowStyle(.automatic)
.windowToolbarStyle(.unified(showsTitle: false))

// ContentView NavigationSplitView
.toolbarBackground(.hidden, for: .windowToolbar)
```

这些配置让标题栏"接近"透明，但 toolbar 区域的白色背景并没有被完全去除。

## View 层级分析

通过在 WindowConfigurator 里遍历 `window.contentView?.superview` 的所有子 view，写入 `/tmp/memory_palace_hierarchy.txt`，得到：

```
NSThemeFrame (1194x834)
  AppKitWindowHostingView (1194x834)
    AppKitPlatformViewHost(WindowConfigurator) (1194x782 at 0,52)  ← y偏移52px = toolbar高度
      WindowObserverView
    AppKitPlatformViewHost(NavigationSplitRepresentable) (1194x834)
      NSView (1194x834)
        NSSplitView (1194x834)
          _NSSplitViewItemViewWrapper (1194x834)  ← detail 列（全窗口宽度，在 sidebar 下面）
            NSHostingView<...ContainerStyleContext> (1194x834)
          _NSSplitViewShadowView (12x834 at 258,0)
          _NSSplitViewItemViewWrapper (258x834)   ← sidebar 列
            NSBlurryAlleywayView (258x834)
            NSContainerConcentricGlassEffectView (250x818 at 8,8)
              ContentHolderView → NSHostingView<...SidebarStyleContext>
          NSSplitDividerView
```

关键发现：
- **toolbar 高度 = 52px**（WindowConfigurator 的 y 偏移量）
- **没有找到 NSTitlebarContainerView / NSTitlebarView / NSToolbarView** — SwiftUI 的 unified toolbar 不像传统 AppKit 那样创建这些 view
- detail 列的 `_NSSplitViewItemViewWrapper` 和其中的 `NSHostingView` 是全窗口大小，但 SwiftUI 内容从 y=52 开始渲染，**顶部 52px 由容器 view 的默认白色背景填充**

## 尝试过的方案

### 1. `titlebarSeparatorStyle = .none`
- **结果**：无效。只去掉分隔线，不影响 toolbar 区域背景色。

### 2. `.toolbar(.hidden, for: .windowToolbar)`
- **结果**：app 卡死无法打开。NavigationSplitView 依赖 window toolbar，完全隐藏会导致无限布局循环。
- **教训**：不能用 SwiftUI 的 `.toolbar(.hidden)` 来消除白条。

### 3. 遍历 NSView 层级，清除 Titlebar 相关 view 的背景
- **目标**：找 class 名含 "Titlebar" / "Toolbar" 的 view，设 `layer.backgroundColor = clear`
- **结果**：白条未消除 + 侧边栏的文字/按钮背景被错误清除。
- **教训**：SwiftUI unified toolbar 不使用传统的 NSTitlebarView，class 名匹配不到真正的白条来源。侧边栏内部 view 被误伤。

### 4. detail 列包 `ZStack { Theme.mainBg.ignoresSafeArea() }`
- **目标**：让 SwiftUI 背景色延伸到 toolbar 下方。
- **结果**：无效。NavigationSplitView 的 detail 列在 SwiftUI 层面被 safe area 约束，`ignoresSafeArea()` 无法穿透到 NSHostingView 的 toolbar 区域。

### 5. 精准 patch 容器链背景（NSThemeFrame → AppKitWindowHostingView → NSSplitView → _NSSplitViewItemViewWrapper）
- **目标**：遍历 view 层级，按 class 名找到容器 view，设置 `layer.backgroundColor` 为暖奶白。跳过侧边栏内部 view。
- **结果**：无效。
- **可能原因**：
  - 这些 view 的白色可能不是来自 `layer.backgroundColor`，而是 `drawRect:` 绘制的
  - SwiftUI 可能在每次布局后重新设置 layer 属性
  - 遗漏了 detail 列内部的 `NSHostingView<...ContainerStyleContext>`（代码里在 NSHostingView 处停止了递归）

## 待排查方向

### A. 补漏：patch detail 列的 NSHostingView（优先试）
方案 5 遗漏了一层：`_NSSplitViewItemViewWrapper` 里的 `NSHostingView<...ContainerStyleContext>`。这个 view 是 detail 列的 SwiftUI 宿主，可能有自己的白色背景覆盖在 wrapper 之上。

```
_NSSplitViewItemViewWrapper (已 patch)
  NSHostingView<...ContainerStyleContext> (未 patch!) ← 补这里
```

sidebar 列的 NSHostingView 不在 wrapper 的直接子级（中间隔了 NSBlurryAlleywayView + ContentHolderView），所以只 patch wrapper 直接子 NSHostingView 不会误伤 sidebar。

### B. 用 NSView.draw() override 而非 layer
`layer.backgroundColor` 可能被 view 的 `drawRect:` 覆盖。可以尝试用 KVO 监听 layer 变化并反复设置，或者用 `NSAppearance` / `NSColor.setSystemColor` 来全局改变默认背景色。

### C. 换 window toolbar 方式
- 试 `.windowToolbarStyle(.unifiedCompact(showsTitle: false))`（toolbar 区域更矮）
- 试去掉 `.windowToolbarStyle` 让系统用默认值
- 试 `window.toolbar?.isVisible = false`（NSToolbar API，不同于 SwiftUI 的 `.toolbar(.hidden)`）
- 试 `window.toolbar = nil`

### D. 全屏时的表现
可能全屏模式下的 toolbar 行为和窗口模式不同。需要分开测试。

### E. 参考其他 macOS 原生 app
Claude 桌面 app 可能是 Electron（不是原生 AppKit），不具参考性。可以参考其他 SwiftUI NavigationSplitView 的 macOS app（如 Apple 的 Notes、Reminders）看它们是否有类似白条。

### F. 彻底绕过：不用 unified toolbar
如果 `.windowToolbarStyle(.unified)` 是根本原因，可以：
- 去掉 unified style
- 把侧边栏切换按钮做成自定义 SwiftUI 按钮（不依赖系统 toolbar）
- 用 `.windowStyle(.hiddenTitleBar)` 完全隐藏标题栏

### G. 用 NSPanel 或自定义 NSWindowController
完全用代码创建窗口，不走 SwiftUI WindowGroup，获得对 titlebar/toolbar 的完全控制。复杂度最高。

## 结论

白条的根源是 **NavigationSplitView 的 unified toolbar 模式下，detail 列的容器 view 链（4层）在 toolbar 区域（顶部 52px）有默认白色背景**。设置 `titlebarAppearsTransparent` 和 `toolbarBackground(.hidden)` 无法完全覆盖这些背景。

最有希望的下一步是 **方向 A**（补 patch NSHostingView）和 **方向 C**（换 toolbar 方式）。如果都不行，**方向 F**（彻底不用 unified toolbar）是最可靠但改动较大的方案。
