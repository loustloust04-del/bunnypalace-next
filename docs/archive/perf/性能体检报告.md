# 记忆宫殿 — 性能体检报告

> 2026-02-26 排查，基于当前代码库全量审阅。

## 概览

当前数据量：1,733 条对话、约 205,981 个 MessageNode。主要性能问题集中在**数据查询方式**上——多处代码在只需要少量数据时做了全量 fetch，导致不必要的内存占用和主线程阻塞。

---

## P0 — 必须尽快修复

### 1. ✅ `chaseMissingAncestors` 全量加载 20 万节点

**文件**: `ConversationViewModel.swift`、`MarkdownExporter.swift`

**问题**: 每次打开一个有缺失祖先节点的分支对话，就把数据库里**全部 20 万个 MessageNode** 一次性读进内存，只为了找几个缺失的 parentId。MarkdownExporter 里有完全相同的代码，批量导出时反复全量 fetch 导致内存耗尽。

**已修复**: 改为按缺失 ID 逐个查询，不再全量 fetch。两处（ViewModel + Exporter）均已修复。

---

### 2. ✅（部分）`performSearch` 缓存失效 ｜ ⏸ 搜索全表扫描搁置

**文件**: `SidebarView.swift` `performSearch()` 方法

**已修复**: `ContentCleaner.clean(node.content, cacheKey: nil)` 的 cacheKey 改为 `node.id`，NSCache 缓存生效，不再每次重复正则清理。

**搁置**: 搜索仍对 20 万节点做 `localizedStandardContains` 全表扫描。加 fetchLimit 会截断结果不可接受；根本解决需要建搜索索引或后台异步搜索，复杂度较高，暂搁置。

---

## P1 — 明显影响体验

### 3. ✅ `performLoad` 在主线程执行全部计算

**文件**: `ConversationViewModel.swift`

**问题**: `performLoad` 的全部工作（fetch + 树构建 + 路径计算）在主线程执行，切换对话时界面冻结。

**已修复**: 拆分为 `buildTreeInBackground`（后台线程用独立 ModelContext 完成 fetch + 树计算）和 `applyTreeData`（主线程应用结果）。后台线程用纯值类型 `NodeInfo` 做树计算，避免跨线程传递 SwiftData 对象。主线程只做快速 re-fetch（SQLite 缓存命中）和结果赋值。

---

### 4. ✅ 收藏/回收站/搜索 N+1 查询

**文件**: `SidebarView.swift`

**问题**: `fetchFavoritedNodes()`、`fetchDeletedNodes()`、`performSearch()` 三处循环逐个查 Conversation 标题，N 条记录 = N 次独立查询。

**已修复**: 提取公共方法 `fetchConversationTitleMap()`，一次查出所有 Conversation 建 titleMap。搜索中的 content-only 分支同样改为一次批量 fetch。

---

## P2 — 可优化项

### 5. ✅ 文件夹模式全量 fetch 再内存过滤

**文件**: `SidebarView.swift` `fetchPage()` 文件夹分支

**问题**: 选了某个文件夹后，先查全部 FavoriteItem 拿到 convId 集合，然后 fetch **全部 Conversation**（convDescriptor 没有过滤 predicate），在内存里用 `.filter` 筛选。

**已修复**: 给 convDescriptor 加了 `isDeleted == false` predicate，数据库层面先过滤掉已删除对话，减少内存中需要过滤的数量。内存过滤仅剩 `convIds.contains` 一项。

---

### 6. ✅（大部分）批量导出重复触发全量加载

**文件**: `SettingsView.swift`、`MarkdownExporter.swift`

**问题**: 批量导出每条对话都调 `MarkdownExporter.loadAndExport`，其中每条都会调 `chaseMissingAncestors` → 全量 fetch 20 万节点。

**已修复**: `chaseMissingAncestors` 已改为按需查询（问题 1），不再全量 fetch，内存占用大幅下降。

**搁置**: 可进一步优化——批量导出开始时一次性构建全局 ancestor lookup，所有对话共享，避免重复查询。当前逐条查询已够用，暂搁置。

---

## 做得好的地方

不全是问题，以下这些设计是正确的：

- **CardFlowView 用了 LazyVStack** — 只渲染可见区域的气泡，不会一次性渲染全部消息
- **BubbleView 文本截断（300 字）** — 避免超长 Markdown 渲染卡顿
- **HoverButtons 状态隔离** — hover 变化不会触发整个气泡重绘
- **对话列表分页加载（pageSize=100）** — 侧边栏不会一次加载全部 1733 条对话
- **ContentCleaner 用了 NSCache** — 清理过的文本有缓存（搜索时 cacheKey 已修复）
- **branchInfoMap 预计算** — 避免渲染时重复计算分支信息
- **effectiveChildrenMap 用了 reserveCapacity** — 减少字典扩容开销
