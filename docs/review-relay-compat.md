## 1. 边界情况（没处理的）

- **DeepSeek 经中转的续轮 400 没实测**：3 家都没有 DeepSeek / 国产思考渠道。中转 host 认不出背后是谁，续轮默认不回传思考，只能靠报错自学（「must be passed back」原文没有点路径，打码后不变，推断能命中；中转若截断嵌套 message 可能认不出）。补测要一把带 DeepSeek 渠道的中转 key。
- **真欠费也会先试一次降上限**：`insufficient_user_quota` 分不出「预扣不够」和「真没钱」，按批准策略先降限重发一次（预算扣 0），再失败才说欠费。
- **降思考档在 OpenAI 兼容路不保证预算**：发的是 `reasoning_effort: low`，中转怎么换成预算没证据；提示不做确定归因。
- **去打码保守**：只有唯一可定位时才还原并学习；认不准只解释，所以打码中转上的参数自学会比官方慢。
- **响应缓存 / 注入系统提示 / 假流式**：只记录（msuicode 同 messages 逐字相同；注入 4k–3.4 万 token 系统提示，走缓存读；ekanw thinking 首字 21s），不处理。

## 2. 与下一模块交互的风险

- **3b 历史回合回传**：与本单无关但同一风险面——DeepSeek 多轮带工具从第二个用户回合起可能 400（见 [review-model-compat-p0](review-model-compat-p0.md) §2.1）。
- **R8 参数过滤**改了 12 个工具执行入口（`ConversationViewModel.executionArgs`）：以后新增工具执行入口必须走它，否则过滤失效。小芽 `AssistantEngine` 的工具循环没接（同 P0 债）。
- **R6 也作用于直连 Gemini OpenAI 兼容口**：原生 `usageMetadata` 分桶优先；`total = prompt + completion` 时不补，不会重复计费。
- **R10 中转才忽略 0**：官方 Anthropic 直连按「字段存在即覆盖」。

## 3. 技术债

- P0 里资料还原的报错样本没换成真样本（plan 写了「顺手」，没做）。
- Fixtures 里 2 个工具调用 id 保留原值（不是凭据）。
- 实测一次超长上下文被 1M 渠道接下，真扣约 59 万 token——以后超长测试只用确认窗口 ≤200k 的渠道，或不测。
- 说明书事实层未同步本单（报错人话新增「无渠道」「分组无权」「预扣」三类），rewrite / build 也未跑。
