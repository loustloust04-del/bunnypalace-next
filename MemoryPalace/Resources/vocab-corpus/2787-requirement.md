# requirement

## 1. 一句话本质

requirement 是一道门槛画在地上——不是你想不想跨，是你**必须**跨，否则后面的路根本不存在。它不是愿望，不是建议，是"没有这个，别的都别谈"。

---

## 2. 词源考古

### 词根词缀拆解

```
re-  +  quir(e)  +  -ment
再次     寻求        名词化后缀
```

- **quir-** ← 拉丁语 **quaerere**（寻找、询问、索要）。这是个大家族词根，query、inquire、acquire、require 全是它的后代。
- **re-** 在这里不是简单的"再次"，而是表示**强化/反复**（intensive prefix）——不是"再找一次"，而是"反复要求直到得到"。这种 re- 的用法在很多拉丁借词里都被磨平了，但它的力度还在。
- **-ment** ← 拉丁语 -mentum → 古法语 -ment，把动作变成"那个东西/那个结果"。

### 历史流变

| 时期 | 形态 | 含义 |
|------|------|------|
| 古典拉丁语 | *requirere* | "反复寻找、追问、需要" |
| 中世纪拉丁语 | *requirementum* | 法律/行政文书中"所要求之事项" |
| 14世纪古法语 | *requirement* | "请求、要求" |
| 14世纪中古英语 | *requirement* | "需求、必需条件" |
| 17世纪起 | requirement | 固化为"必要条件、规定" |

**关键转折**：从"反复寻找"到"必须满足的条件"——动作变成了静态门槛。这个漂移发生在法律和行政语境中：当国王"反复要求"某样东西时，那东西就变成了制度性的"必须满足项"。**权力把动词凝固成了名词。**

### 文化地层

requirement 在现代英语里有一种微妙的**非人格化**特质——它不像 demand 那样有个活生生的人在喊，而是像一条写在墙上的规则。这正是它从行政/法律语境继承来的：requirement 是制度的声音，不是个人的声音。

## 3. 故事 / 画面

想象一个机场安检口。

你拖着箱子往前走，前面有一块电子屏，上面列着几行字：

- 护照 ✓
- 登机牌 ✓
- 液体 ≤100ml ✓

这些不是"建议你带"，不是"最好有"——**少任何一项，你就走不过去。** 屏幕不会跟你商量，安检员不会因为你态度好就放行。这些条件和你是谁、你什么心情、你的故事多感人完全无关。

这就是 requirement 的本质：**一道无人格的关卡。** 它不关心你的理由，只关心你是否满足它。

而且注意——那块屏幕上写的东西，是**别人**替你决定的。requirement 永远暗含着一个你看不见的制定者：可能是系统、制度、组织、自然规律。

## 4. 多面体：核心义项展开

### 义项 A：必要条件（最核心）

> *A valid passport is a requirement for international travel.*
> 有效护照是国际旅行的必要条件。

与本质的关系：最纯粹的"门槛"——没有它，后面的事不成立。

### 义项 B：需求（软件/工程语境）

> *The client changed the requirements halfway through the project.*
> 客户在项目进行到一半时改了需求。

与本质的关系：仍然是"门槛"，但这里的门槛是"做出来的东西必须长这样"。requirement 在工程语境里 = 验收标准。不满足 = 不算完成。

### 义项 C：规定、法定要求

> *There's a legal requirement to report income over $600.*
> 法律规定收入超过 600 美元必须申报。

与本质的关系：制度性门槛。这里的"必须"带有惩罚后果——不是你过不了关，是你会被追责。

### 义项 D：需要的东西（复数形式 requirements = 所需物品/条件清单）

> *Please check the system requirements before installing.*
> 安装前请检查系统要求。

与本质的关系：门槛的具象化——一张清单，每一项都是"非满足不可"。

**底层统一性**：所有义项都共享同一个结构——"X 是达成 Y 的**非可选前提**"。无论 X 是护照、功能规格、法律条文还是硬件配置，requirement 永远是那条"没有就别谈"的线。

## 5. 裂缝标注

### 常见误用场景

**❌ 把 requirement 当 request 用**

requirement 是"必须满足的条件"，request 是"请求/恳求"。一个是铁门，一个是敲门。

- ❌ *I sent a requirement to the team to help me.* （你不是在设门槛，你是在求助）
- ✓ *I sent a request to the team for help.*

**❌ 在非正式场合用 requirement 显得过于僵硬**

- 对朋友说 "My requirement is that you arrive by 8" → 太冷，像制度文件。说 "I need you here by 8" 就好。

### 易混近义词辨析

| 词 | 区别 |
|---|---|
| **need** | 更主观，更人性化。"I need coffee" 是你的感受；"Coffee is a requirement" 是规定。 |
| **demand** | 有明确的施压者在。demand 是一个人站在你面前喊；requirement 是一条写在墙上的规则。 |
| **prerequisite** | requirement 的子集——特指"在时间上必须先满足的"。所有 prerequisite 都是 requirement，但反过来不一定。 |
| **necessity** | 更哲学/抽象，强调"本质上不可缺少"。requirement 强调"被规定为不可缺少"（有制定者）。 |

**场景对比**：

- 大学说"GPA 3.0 is a requirement for graduation" → 制度规定
- 你说"Sleep is a necessity" → 生理本质
- 老板说"I demand an explanation" → 个人在施压
- 课程说"Calculus I is a prerequisite for Calculus II" → 时序前提

### 中文母语者陷阱

**"要求" ≠ requirement**

中文的"要求"既能当动词（"我要求你道歉"）又能当名词（"这是基本要求"），但英文里这两个用法分属不同的词：

- "我要求你道歉" → I **demand** an apology / I **require** an apology
- "入学要求" → admission **requirements**
- "提出要求" → make a **request** / set a **requirement**（取决于语境）

中文母语者经常把"要求"的所有语义都塞进 requirement 里，但 requirement 只覆盖"条件/规定"这一面。

## 6. 搭配与语域

### 高频搭配

| 搭配 | 语境 |
|------|------|
| **meet/fulfill requirements** | "满足要求"——最标准的搭配，过安检的感觉 |
| **minimum requirement** | 最低门槛——刚好够过线 |
| **legal/regulatory requirement** | 法定要求——违反有后果 |
| **system requirements** | 软硬件配置需求——技术门槛 |
| **entry requirement** | 入学/入境条件 |
| **requirement for + 名词/动名词** | "...的必要条件" |
| **gather/define requirements** | 收集/定义需求——工程语境 |
| **requirements specification (spec)** | 需求规格文档——软件工程核心文档 |

### 语域标注

**偏正式**。requirement 天然带有制度感、文件感。日常口语更常用 need / what you need / what's needed。

- 学术写作 ✓✓✓
- 商务邮件 ✓✓✓
- 技术文档 ✓✓✓
- 法律文本 ✓✓✓
- 朋友聊天 △（会显得很官方）

### 活用示范

> *"The only requirement for joining this club is a willingness to look stupid."*
> "加入这个俱乐部唯一的要求是愿意出丑。"

——用 requirement 的正式感制造反差幽默。把一件随意的事套上制度框架，好笑就在这个错位里。

> *"Empathy isn't a nice-to-have. It's a requirement."*
> "共情不是锦上添花，是必要条件。"

——利用 requirement 的"非可选"力度来做修辞升级。把软性品质硬化为门槛。

## 7. 跨语言映射

**中文"要求"** vs **requirement**：中文的"要求"是动词和名词的合体，覆盖了 requirement + demand + request 的部分领地。requirement 只取其中"条件/规定"这一截。

**日语「要件」（ようけん）**：几乎精确对应 requirement 的法律/技术义。"契約の要件" = requirements of a contract。但日语日常不太用这个词，更口语的是「必要なもの」。

**德语 Anforderung**：结构类似——an（对着）+ Forderung（要求）= "对着你提出的要求"。在技术文档中和 requirement 一一对应（Anforderungsspezifikation = requirements specification）。

**法语 exigence**：比 requirement 更有情绪张力。exigence 带着"苛刻、严格"的温度，而 requirement 更中性冷淡。法语的 requirement（条件义）更常用 **condition requise**。
